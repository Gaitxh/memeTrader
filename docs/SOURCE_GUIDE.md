# 国际信息源与分钟级运行指南

## 目标

本项目不试图在个人电脑上和专业低延迟做市商争夺毫秒，而是争取下面这个现实窗口：

```text
一手事件出现
→ 事件开始跨账号/跨社区扩散
→ 对应 Token 创建或旧 Token 被重新激活
→ 机器人在几十秒到几分钟内完成事件、Token、主盘与风险确认
```

对于真正的大热点，传播周期通常不止几秒。机器人更重视“少量高质量一手账号 + 新 Token 反向搜索 + 多来源确认”，而不是盲目每秒抓全网。

## 延迟分层

| 通道 | 典型目标延迟 | 当前方式 | 备注 |
|---|---:|---|---|
| Pump 新 Token | 1–5 秒 | 免费 WebSocket | 只做创建/迁移发现，不买全部新币 |
| 已登录社交页面 | 5–60 秒 | 浏览器 DOM 增量观察 | 依赖页面保持打开、不被休眠 |
| 新 DEX 池 | 30–90 秒 | GeckoTerminal 轮询 | Solana/BSC 免费补充 |
| 候选报价 | 5–20 秒 | DexScreener 按需查询 | 只查晋级候选，避免打满限频 |
| RSS/聚合新闻 | 1–5 分钟 | RSS/Atom | 用于独立确认、反向搜索和媒体扩散 |

这些是工程目标，不是平台保证。真实延迟会受平台刷新、网络、标签页休眠和免费服务限频影响。

## 来源优先级

### A：最强一手证据

- 名人、政治人物、项目方、机构的公开账号；
- 官方网站或官方公告；
- 帖子正文明确给出 CA；
- 链上创建事件或迁移事件。

官方账号发布准确 CA 时，CA 关联优先于同名币的动量。但官方身份仍不能绕过 honeypot、不可卖、税率、流动性和仓位风控。

### B：强扩散证据

- 多个互不依赖的记者、媒体、社区或平台同时出现；
- 账号原始帖子被多个独立群体讨论；
- 搜索量、帖子数量、独立作者和新买家同时增长；
- Token 社交链接、名称、图片和事件高度一致。

### C：弱线索

- 单一 KOL 喊单；
- 交易群转发；
- 热榜聚合页；
- 只有价格上涨，没有明确现实事件；
- 只有 Token 名称相似。

C 类可以触发进一步调查，但不能单独触发买入。

### D：结果和事后信息

- 交易所后来上线；
- ATH、最终市值和最终 Holder；
- 后来被称为“主盘”；
- 事后聪明钱标签；
- 新闻回顾文章中的涨幅；
- 事后诉讼、崩盘或 Rug 结论。

D 类只作为 outcome/label，用于评价当时判断，不能参与旧时点决策。

## 平台配置建议

### X

建议建立几个低噪声 List，而不是只打开 For You：

1. 世界政治和高影响力名人；
2. 科技、AI、娱乐、体育和动物热点；
3. 一手记者与突发新闻账号；
4. Solana/Pump、BNB/Four.meme、Base 社区；
5. 只转发 CA 的交易群体单独放置，降低其证据权重。

扩展读取页面新出现的公开帖子，保留本机接收时间。页面初次加载的旧帖子只有在发布时间足够新时才进入事件特征。

### Truth Social

重点账号页通常比后续媒体报道更早。适合官方直接发行、政治人物声明、身份确认。打开明确账号页面，不要依赖平台首页推荐流。

### Telegram

当前零配置方式是打开 `t.me` 公共频道页面。它只用于公共频道，不读取私聊。需要更稳定的登录态频道监听时，可后续启用 Telethon，但 Telegram 的 `api_id/api_hash` 需要用户自己申请，且 Session 文件必须留在本机并排除 Git。

### Reddit

可组合：

- 浏览器中的 `/new`；
- Subreddit RSS；
- 少量明确社区，而不是抓整个 Reddit。

Reddit 适合发现社区叙事发酵，但通常不应被当作官方 Token 身份来源，除非帖子提供可交叉核验的 CA。

### Bluesky

机器人支持公共搜索 API，并在 `public.api.bsky.app` 不可用时回退到 `api.bsky.app`。公共端点在部分网络/CDN 节点可能返回 403，因此浏览器页面仍是备用来源。

### Mastodon / Truth Social 类接口

支持配置公开 Mastodon-compatible JSON 端点。公开时间线是否允许匿名读取由实例决定。流式接口在较新的 Mastodon 版本通常需要用户令牌，所以默认只轮询明确公开端点。

### YouTube

官方频道 RSS 更稳定；浏览器页面作为补充。适合发布会、直播标题、采访、官方视频和突然走红的文化内容。

### Instagram、Threads、TikTok

默认只使用已登录浏览器标签页。DOM 会变，扩展可能需要随平台改版更新 selector。心跳正常但 `forwarded=0` 持续很久，意味着页面没有新帖、页面被冻结或 selector 已失效。

## 电脑端运行方式

建议：

- 创建一个专门用于 memeTrader 的 Chrome/Edge Profile；
- 只登录允许机器人观察的账号；
- 不在该 Profile 中处理私信；
- 将重点标签页设为“不休眠”；
- 屏幕可锁定，但浏览器和机器人进程需要继续运行；
- 每日检查 `source_health`；
- 每日备份 SQLite；
- Windows 登录后自动启动机器人，浏览器使用“继续上次打开的页面”。

## 免费接口使用原则

- 只保存首次观察结果，不因接口短暂失败重置时间；
- 每个主机限速和短 TTL 缓存；
- 429 按 `Retry-After` 退避；
- 先本地去重，再调用外部服务；
- 新 Token 先用免费流发现，只有出现流动性和交易活动后才报价；
- 事件晋级后才搜索同名 Token；
- 安全服务只查最终候选；
- 某一可选来源失败时降级，不阻塞全部采集。

## 当前不采用的方式

- 为了毫秒级速度购买专用交易流和昂贵 RPC；
- 轮询全部 X 或全网关键词；
- 未经授权地导出浏览器 Cookie；
- 读取私信或私人群聊；
- 将账号 Session、Cookie、私钥提交到 Git；
- 对每条帖子调用 GPT；
- 让 LLM 直接控制钱包；
- 看到名称一致就立即买入。
