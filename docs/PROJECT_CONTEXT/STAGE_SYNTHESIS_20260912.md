## 一、发现并修复的真实缺陷（3 个，全部已加载验证）

### 缺陷 1（可达性·崩溃级）：新增家族读取了一个永不存在的特征键
- **现象**：全系统只有 4 种机制触发；`TypeError: '>=' not supported between NoneType and int` 累计 398 次。
- **根因**：`dex_trajectory.derive()` 只把池深发布在 `current.liquidity_usd`，从不发布顶层 `liquidity_usd`；家族机制读顶层键 → 每帧在深度守卫处提前返回，编号机制 1–27 从未执行。
- **量化**：43 条标定向量中可触发 **1 → 39**。
- **修复**：depth 缺失时回落当前帧、三处判空、窗口变量统一绑定。
- **加载后**：非零机制 4 → 34+，出信号臂 0 → 54。

### 缺陷 2（可达性·崩溃级）：信号循环被早先提交重新嵌套
- **根因**：commit `4ed7101` 把覆盖报价块插进 `for identity in quotes:` 与 `if identity in fresh144:` 之间，导致 trajectory144/145、微观结构、event-clone 信号**每周期最多只处理最后一个 identity**；无帧周期抛 `UnboundLocalError` 392 次。
- **修复**：整块后移 + 循环变量改名。加载后两条错误计数**停止增长**。

### 缺陷 3（可达性·供应级）：安全带被"必须严格上涨"卡死
- **现象**：最安全的 FDV/深度带长期几乎不交易（ready 2 vs 深池带 75）。
- **定位**：加装逐条件计数器（621 帧）——**严格上涨只通过 2.7% 的帧，而"不下跌"通过 91.1%**（引擎连续帧多为同价重报价）；安全带区间另叠加 3.9 倍差距。
- **修复**：新增"不下跌"变体；**实测供应放大 43 倍**（core 1 → steady 43–57）。
- **附带发现**：中段带 ready 仍为 0，计数显示瓶颈是**我自己加的"买盘≥55%"条件**（86 帧中 0 帧满足，而全体 55.5%）——该条件**不在第 3 轮写销带实测之内**，故删除而非调参 → ready 0 → **92**。

> 三个缺陷的共同点：**不是策略逻辑错，而是"策略永远看不到/看不到足够多的机会"**。这也直接回答了目标首段的疑问——"已发现的代币未能充分进入策略判断流程"在会话开始时**确实成立**，且有三处独立原因。

## 四、被证据支持的结论 vs 被证伪的解释

**支持：**
1. 写销尾部主要是**入场选择问题**：分带差 23 倍，且分链独立成立、分半样本稳定；修复后队列 455 笔 0 写销、压力窗口 0/17。
2. 硬止损是**已实现亏损的主要来源**（占总净亏损 100%+）。
3. 止损深度会**跳空超出阈值**（中位 6.4 点），且**随持仓时间恶化**；极端 FDV/深度档是断崖。
4. "严格上涨"帧条件在真实帧流上**几乎不可满足**（2.7%），是安全带长期低产的直接原因。

**证伪（我自己的假设，已如实记录）：**
1. ~~结算滑点导致止损更深~~ → 结算价缺口 p50 = 0.00%。
2. ~~深度下限是安全带瓶颈~~ → 放宽到 3000U 后触发次数不变。
3. ~~安全带区间稀缺~~ → 该区间占池龄窗口内 51.9% 的帧。
4. ~~止损时点方案明显占优~~ → 样本从 6v4 增加后差距收窄（+1.00/+0.72 vs +0.85/+0.48），**无可靠赢家**。
5. ~~买盘≥55% 是安全带应保留的条件~~ → 它是我的添加、不在实测带内，且是 0 供应的直接原因。

## 五、给现有策略的修订建议（**仅文档化，未实施**）

约束要求"新策略必须以额外策略形式加入，不得修改/替换/覆盖现有策略"。因此以下仅为建议，供用户决定是否以**新臂**形式落地：

1. **止损合同是最优先的修订点**：现有 340+ 条臂绝大多数使用固定 −20% 止损、无宽限期、无确认、无时点方案；在本会话实测中，该合同贡献了全部净亏损。建议以新臂形式为其主力入场族各配一份"宽限+确认"或"时点"合同做同入场对照。
2. **入场存活带**：FDV/深度 <1 与池龄 <30 分钟的组合（54% 写销）值得在**新臂**层面规避；已有 4 条 band 臂在跑。
3. **单币集中度**：29 条臂同时持有一个代币的事件说明组合层缺少敞口上限。这**超出"仅新增臂"的能力范围**，需要引擎层支持，已作为独立议题记录，未擅自实施。
4. **不要用放宽安全带条件来提升交易量**：本会话已两次证明那只会把"安全带"变成"没有带"。
