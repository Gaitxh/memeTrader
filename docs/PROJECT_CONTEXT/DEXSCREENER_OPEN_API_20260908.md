本轮按用户最新要求调研官方接口，并继续实现与发现、请求额度和数据真实性直接相关的修复。现有策略和资金期保持，未恢复策略扩张或自动研究。

## 已核验的新能力

官方现在列出资料、资料更新、CTO、广告、Boost latest/top 共六个 WebSocket 路径。本机不提供密钥，实测 `wss://api.dexscreener.com/token-profiles/recent-updates/v1` 和 `/token-boosts/latest/v1` 均返回 101。首次消息为 `{limit,data}`，各含90条；资料更新随后收到2条、29条组成的数组消息。握手约0.53/0.58秒，仅为单次连接时延，不是链上事件到本地的端到端延迟。首次列表及后续消息包含较早的资料更新时间，不能把每条推送称为刚发行的新币。官方没有在该页面列出价格、成交或流动性流。来源：[官方 WebSocket 文档](https://docs.dexscreener.com/api/websockets)。

## 本轮实现

1. **资料更新与Boost推送。** 复用已安装 websockets、来源链接和发现曝光表，收到消息后进入现有补全队列。保留REST回退；消息重放按Token和内容去重，缓存有界；逐Token让位给持仓工作。推广角色保持promotion，来源证据不直接产生买入。消息接收时间、握手初始列表标识和原始资料更新时间分开保存。
2. **保留共享行情预算。** 推送本身不发逐币行情请求，行情仍由现有15秒、最多30目标的小批任务处理。更快的是发现送达，不能承诺所有候选都在15秒内完成补全。没有增加Agent调用、付费服务或策略账户。
3. **补齐Dex终态429的共享冷却。** 原有250毫秒主机节流保留；新增响应给出的Retry-After截止时间，包含不自动重试的原池查询和最终重试仍失败的发现路径。同步已有Runtime冷却，持仓任务可及时延期，不占住执行槽等待。
4. **拒绝明确陈旧的上游缓存。** 原池检查加入HTTP Age及该HTTP收件后经过时间。相同缓存generation复用旧observedAt时，不重复累加旧观测时长。原有本地15秒检查独立保留；不把max-age/s-maxage当实际年龄，不更改历史观察时间。

## 未解决的真实边界

前次针对两个Solana Pumpfun持仓，`token-pairs`返回原池和价格，但`liquidity=null`；Robinhood样本返回空列表。新增发现流和Metas不能补出这些字段。Gecko补源也不能保证持续15秒内的新鲜完整原池数据。不能把新价格与旧流动性拼为“新完整帧”，也不能把虚拟储备当真实可撤流动性。

实时可派生的候选包括同池流动性变化、成交量/流动性、买卖笔数不平衡、多池集中度和分类广度。它们必须基于同池、同口径、严格前向有效帧；滚动5分钟计数之差不等于最近几秒真实成交数。缺值和过期时不计算伪特征。尚无自然前向证据证明新增来源或这些候选有alpha。

原始实测保存在 `data/research/dex_open_api_probe_20260908.json`，原池反例在 `data/research/dex_token_pairs_verification_20260908.json`。两者均为本地研究工件，不提交数据库或私有配置。
