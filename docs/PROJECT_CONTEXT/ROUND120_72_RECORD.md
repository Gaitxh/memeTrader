## 1. 准入级联的真实结构（逐行读 `store.py:28150-28296`）

```
28150-28213  按 entry_filter['contract'] 分派到不同的信号函数：
             capital_observation_signal / lifecycle_signal / impulse_signal / renewal_signal /
             runner_signal / archive_signal / research_signal / resource_entry_signal，
             默认回落到 pattern_signal
28214-28215  封禁：pattern_already_enrolled_at_this_pool
28216-28217  封禁：entry_blocked[arm]（含 strategy_open_slot_limit 等）
28218-28219  封禁：round2_chase_original_opportunity_consumed

28228-28237  admitted_arms = active AND post_valid AND in pending AND previous is not None
             AND observed_at > previous.evaluated_at AND not already_bought AND not entry_blocked
             AND（cohort / event-key 条件）
28241-28269  信号后兼容性复核，可把已准入的臂**移除**

```

**这条链解释了为什么第 71 轮看到"7,154 条决策 100% admitted"**：
`entry_decisions` 只记录**最终走到写入那一步的臂**，而绝大多数臂在
`28228` 那一步之前就已经不在 `admitted_arms` 里了。**"100% admitted"不是没有闸门，
而是闸门在更上游。**

## 3. 判定：这个闸门是"筛选"还是"走不下去"

这是本轮的方法论核心。我用**不需要价格数据、因此不可能有选择偏差**的量来区分：

| 检验 | `await_distinct_dex_trajectory_frame` | 含义 |
|---|---|---|
| 占全部逐臂判定 | **46.41%** | 最大 |
| 覆盖 token | **38.7%**（不是 100%） | **有选择性，不是人人必经** |
| 触及该状态的 (token, arm) 配对 | **1,121,875** | — |
| **其中最终状态仍是它** | **98.9%**（1,109,525） | **候选流终止于此** |
| 第一次进入后出现过别的原因 | **2.6%**（28,614） | 逃逸极罕见 |
| 停留帧数（换状态前） | p50 **1**、p75 2、p90 4、max 47 | 多数配对只在这个状态上出现一帧 |
| 该原因内 token 转化率 | 1.03%（基准 0.46%） | 2.2 倍，**不是 0** |

**结论**：它**不是**一个把好标的筛掉的过严规则——被它拦住的 token 转化率确实略高于基准。
它是**候选流的结构性终点**：触及它的配对里 **98.9% 到此为止**，
只有 **2.6%** 在之后出现过任何别的原因。

### 3.1 我在这条结论上先是算错了统计量（必须记录）

我第一版的 `outcomes_readout.py` 打印过一个"逃逸率 40.6%"，而手工探针给出 0.4%。
两个数都不可直接引用，因为**"逃逸率"本身有歧义**——配对会振荡
（gate → 别的原因 → gate → …），所以"有没有逃逸"取决于你问的是**第一次**出现还是**每一次**出现。
同一份数据上三种问法给出三个数：

| 问法 | 结果 |
|---|---|
| A. 第一次进入后不再出现该原因 | 67.5% |
| B. 每一次出现都是最后一次 | 98.9% |
| C. 第一次进入后出现过任何别的原因 | 2.6% |

而且第一版脚本把 A 的分子除以了**判定数**而不是**配对数**，得到 40.6%——**又一个规则 26 违规**
（同一轮里第二次）。**最终采用的量是"最终状态占比"（98.9%），因为它不需要在 A/B/C 之间做选择。**
`outcomes_readout.py` 已改为打印 `ends%`（触及该原因的配对中，最终仍停在该原因的比例）
并把这个歧义写进了脚本文档。

**机制**（接第 64–65 轮，现在有了直接观测）：
三个**不同**的轨迹帧需要 60–90 秒连续观测，而提供方每 ~30.1 秒才给一次新信息
（仅 28.8% 的轮询有变化）。于是绝大多数候选**等不到第三个不同帧**，
配对就停在这个状态上不再前进。**这不是阈值过严，是观测供给不足。**

它打印 `verdicts / tokens / pairs / rate / ends% / final%` 并对每个歧义列写了读法说明，

### P1：`wait_passive_cohort_opportunity` 与 `await_distinct_dex_trajectory_frame` 高度重合

两者都覆盖 38.8% 的 token、转化率都恰好 1.04%，**几乎可以肯定作用于同一批候选**

还是**重复记账**；如果是重复记账，那 29.49% 的占比会夸大被动等待的规模。
**这是"准确性"目标下值得做的一项。**
