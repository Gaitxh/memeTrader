# 第 83 轮记录：订单流退出——**否决**。参数不稳、对赢家帮助更小，而更简单的价格规则已足够

日期：2026-09-13
前置：`ROUND120_82_RECORD.md`
本轮性质：**测试一个用户 mandate 明确点名的方向（信号衰减退出 / 派生特征），并给出否决的理由。**
没有改任何策略、阈值或运行时行为。

---

## 0. 一句话结论

1. 用户 mandate 点名"信号衰减退出"，且要求"优先基于现有可获得的数据与特征，设计高质量的派生/近似特征"。
   **mark 历史里有现成的订单流字段，而没有任何退出规则读它们**：
   `volume_5m_usd`、`buys_5m`、`sells_5m`，**33,995 条 mark 全部有值（100%）**。
   **已部署的退出全部只看价格（硬止损、追踪回撤、止盈档）或流动性（粉尘核销）。**
2. **我测了三种订单流退出规则**（流量崩塌、卖压翻转、二者组合），全部遵守因果性
   （只用来及当前的 mark、在下一个 mark 成交、用引擎自己的 `0.96R−1` 核）：
   **流量崩塌在"成交量跌到自身运行最大值的 25% 以下"时合计 +40.5**，
   而第 82 轮的价格追踪回撤基线是 **−57.3**，实际是 **−1,338.0**。
   **按头条数字，流量规则看起来更好。**
3. **但它经不起稳健性检验，我否决它：**

   | 检验 | 结果 | 判定 |
   |---|---|---|
   | **单调性** | 阈值 0.10→0.75 依次为 **+11.3 / −9.2 / +66.2 / +40.5 / −3.0 / +62.8 / +23.8 / −8.7 / −87.3** | **符号反复翻转，不单调** |
   | 对**赢家**的帮助 | 流量 **+44.9** vs 价格 **+97.1** | **价格规则更好** |
   | 是否只是价格规则的伪装 | 两者同时触发仅 **6.7%**；同时触发时中位相差 **−11 个 mark** | 确实是**不同**的信号 |
   | 对**跑起来的大金狗** | 流量 **+426.9** vs 价格 **+392.9** | 流量略好，但差距很小 |

4. **参数在 0.05 的步长上就翻转符号**（+66.2 → +40.5 → −3.0 → +62.8），
   而**跨越自身参数的摆幅（128U）大于它相对价格规则的优势（98U）**。
   **这不是机制，是扫描出来的最好格子。** 第 26 轮的择优陷阱。
5. **∴ 否决订单流退出，并保留更简单的价格规则。**
   **本轮的可操作结论是"不要做什么"**，这本身有价值：
   它阻止了一个看起来更花哨、实则不稳健的方向进入前向验证队列。

## 1. 为什么这个方向看起来有希望（以及为什么它不是）

**希望来自两点，都是真的：**
- **订单流字段完全可得且全部有值**（33,995/33,995），不需要新增采集——正好符合用户
  "优先用现有数据设计派生特征"的要求。
- **它与价格信号确实不同**：只有 **6.7%** 的仓位两者同时触发，
  同时触发时中位相差 **−11 个 mark**（流量**更早**）。
  且在赢家组上都是正的改善。**它不是在重复价格规则。**

**否证来自三点，也都是真的：**
- **参数不稳定**（见上表）。一个真实机制应该在相邻参数上平滑变化；
  这里的符号在 0.05 步长上翻转，**说明它捕捉的是噪声**。
- **对赢家的帮助只有价格规则的一半**（+44.9 vs +97.1）——
  而"金狗拿不住"恰恰是关于赢家的，所以这一项权重最高。
- **它对"跑起来的大金狗"的改善（+426.9）只比价格规则（+392.9）高 34U**，
  而为此要多引入一族参数（阈值 + 可能的窗口）。

---

## 2. 一个必须写明的口径问题（我自己方法的弱点）

**价格规则与流量规则是在不同的 mark 子集上评估的。**
流量规则会**跳过没有流量字段的 mark**（本轮实测这些 mark 占比 0%，所以在本数据上影响为零），
但如果将来数据质量变化，这个对比就会失真。**脚本已把两者的计数分别打印。**

另外：**本轮的流量规则相对价格规则有"扫描次数"的不公平优势**——
价格规则我只取了 dd=25% 一个点，而流量规则扫了三个阈值。
**但我没有为流量规则做完整扫描来"给它一个公平机会"**，因为单调性检验已经表明
**再扫下去只会找到更极端的格子**（0.75 处是 −87.3，0.20 处是 +66.2，同一个家族）。
**在符号翻转的家族上继续扫，是在增加择优风险，不是在做检验。**

## 3. 对用户的直接回答

**用户 mandate 要求"信号衰减退出"作为一个维度。本轮的实测回答是：
在这个系统现有的数据与时间尺度上，订单流衰减不是一个稳定的退出信号。**

更重要的连带结论——**第 82 轮的假设因此变得更清晰，而不是更模糊**：

> **价格追踪回撤（在 −57.3，赢家 +97.1）与订单流崩塌（+40.5，赢家 +44.9）都比实际（−1,338.0）
> 好一个数量级；而两者之间的差别只有几十 U，且订单流那一族的差别不稳定。**
> **∴ 值得前向验证的是"有没有一个生效的追踪退出"，不是"用哪种信号驱动它"。**

**这与第 82 轮的结论一致并加强它**：
第 82 轮测出"激活阈值的选择只值 7U 量级，而追踪退出是否生效值 1,200U 量级"；
本轮又测出"换一个更复杂的信号族只值几十 U，且不稳定"。
**两个独立的维度都指向同一件事：问题在覆盖，不在精巧度。**

## 4. 边界（一起读）

- **样本内、单 epoch、下一个 mark 成交、只用引擎自己的 0.96 折价、未建模 4% 滑点。**
- **mark 流重复为主**（第 79 轮：不同价格数/mark 数 p50 = 0.24），两 mark 之间的走法不可见。
- **流量字段是提供方的滚动 5 分钟聚合**，不是原始逐笔；
  所谓"崩塌"可能反映的是提供方自己的窗口机制，而不是池子的真实变化。
  **这是本条否决里最实质的一条技术不确定性**，也是我没有把它推进到前向验证的原因之一。
- 第 43 轮关于**止盈侧**的结论不能跨引到追踪或流量侧。

**本轮不改任何东西，不新建模块。**
