## 1. 我为什么要查这个

`exits150.py` 的 `_COMMON` 写着 `notional_usd=1.0`，而本账期的 `policy_notional_usd` 是 20.0。
如果各臂的仓位规模相差 20 倍，那么 **"U/仓" 在不同臂之间根本不可比**——
而我在第 57 轮的对比、以及检查点里的"实时点名"表**恰恰把退出臂与下限臂的 U/仓并列**。

这与第 52 轮（公式错）和第 27 轮（`closed` 均值不可比）是同一类错误，所以先自查。

**代码路径**：`runtime.py:1292/1304/1323/1331` 一律传

## 4. 影响范围（逐条界定，避免夸大）

**不受影响的**（我逐一核对过）：
- 第 40/43 轮的栈投影：用的是**每仓位真实的 `stake_usd`**，所以那些 U 数字是对的。
- 第 28 轮的"已部署 4,400U"：由真实仓位算出（220 × 20 = 4,400）✓。
- 第 57 轮的四组对比与检查点表格：全部同规模（见 §2）。
- `exit_ladder150` 的单因子性质：四个臂**都是 20U**，规模一致，剂量-反应不受影响。
- 任何现金流/盈亏对账：都以真实 `stake_usd` 为准。

**受影响的**：
- **风险读数的表述**：`exits150.py` 的 "1U×4仓" 让人以为每臂风险 4U，
  实际每个仓位风险 **20U**——**低估 20 倍**。同类表述也出现在 `exit_ladder150.py`。
- **一个"看起来像风控上限"的字段其实是空的**：这比字段缺失更危险，
  因为它会让读代码的人以为自己看到了一个生效的风险限额。

## 5. 处置：**只加注释，不改任何已注册文本**

在 `exits150.py` 的 `_COMMON` 与 `exit_ladder150.py` 的 `_COMMON` 处各加一段注释，
写清：实测证据、真实来源（全局 `paper.max_position_usd`）、受影响的模块、
以及**应当忽略描述里的 "1U" 表述**。

**为什么不改描述文本**：这些描述是**已注册臂的契约文本**（落在
`policy_additions.policy_json`）。改文本属于改动在跑臂的注册内容——
与第 57 轮 `exit150_full25_v1` 描述不准时同一处置理由：
**更准确的措辞收益 < 契约身份漂移的风险**。而注释不在任何契约里，零行为影响。

已验证为**纯注释改动**：`git diff --stat` 为 **20 行新增、0 行删除**；
26 个测试通过；`OVERRIDES` 的 `notional_usd` 与四个档位值均未改变。
