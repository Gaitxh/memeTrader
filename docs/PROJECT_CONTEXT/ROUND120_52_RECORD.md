## 1. 缺陷：我用了错的经济收益公式（影响第 39/40/43/51 轮）

我第 43 轮用的：

```python
econ = (1-BUY)/(1+SELL) * (px / entry_execution_price_usd) - 1 - 2*60/1e4
```

**两处错**：

1. **买入滑点被扣了两次**。`entry_execution_price_usd` **本身已经含 4% 买入滑点**
   （实测 mean `ep/sig = 1.0398`），再除以 `(1+SELL)` 等于又扣一遍。
2. **1.2% 的费用不存在**。当前生效的 paper 执行配置里
   `additional_fee_usd_each_fill = 0.0`，所以 `2*60/1e4` 那一项是无中生有。

**生产内核**（`store.py:25359-25363` 的 v20 修正公式）：

```
stake_usd * remaining_raw/initial_raw * current_price / entry_execution_price_usd * 0.96
=>  econ = 0.96 * R - 1        (R = price / entry_execution_price_usd)
```

## 2. 一手验证（不靠子 Agent 的转述）

`chain_meme_trader_marks.trigger_evidence_json.pre_trigger.economic_return` 存的是
**引擎在决策那一刻自己算出来的数**。把每条 mark 与其仓位 join 取得入场价后，两个公式各自对分：

| 公式 | 与引擎记录**完全相等**（\|误差\|<1e-9） | 平均绝对误差 |
|---|---|---|
| **`0.96R − 1`（生产内核）** | **1,265 / 1,300** | 0.00997 |
| `(1−BUY)/(1+SELL)R − 1 − 2·60/1e4`（我用的） | **0 / 1,300** | 0.04896 |

在 **107 条真实的 `market_mark_take_profit`** 记录上：生产内核 **86/107 完全相等**，我的 **0/107**。

**结论：公式缺陷成立。** 我的公式在每个目标档位上都**严格约 5.1%**：

| 目标 | 我的公式要求 R ≥ | 生产内核要求 R ≥ |
|---|---|---|
| +10% | 1.2047 | 1.1458 |
| +15% | **1.2588** | **1.1979** |
| +20% | 1.3130 | 1.2500 |

**更严的阈值只会让止盈*少*触发**（实测：被保留集合上，我的内核触发 180 次，正确内核 207 次），
所以凡是用旧公式的重放，都**低估**了止盈的收益与触及率。

## 4. 收窄后的正确表述（这是本轮最重要的产出）

子 Agent 的敏感性网格把我原来的**过度概括**证伪了，我用自己的方法复现了同一模式：

| 涨幅上限 | 保留仓位 | 止盈 +15% 增量 | 90% CI | 含零？ |
|---|---|---|---|---|
| ≤10% | 818 | +160.8U | [−472, +844] | 是 |
| **≤15%（已部署）** | **894** | **+476.6U** | **[−340, +1,469]** | **是** |
| ≤20% | 964 | +728.2U | [−194, +1,751] | 是 |
| **无上限** | 1,590 | **+3,581.4U** | **[+1,004, +6,882]** | **否** |

**所以：**

- **零增量是"已部署的 ≤15% 涨幅上限"的性质，不是"入场过滤"的一般性质。**
  一旦取消涨幅上限，止盈的增量立刻**显著为正**（+3,581U，CI 排除零）。
- 我第 43 轮写的"止盈是入场过滤的纯替代品"**过度概括，撤回**。正确表述是：
  **在已部署的 ≤15% 涨幅上限之下，止盈是冗余的**——因为涨幅上限已经先把那批"入场前已经涨过、
  后来会死"的池子挡在外面了。
- **替代机制本身仍然成立**：止盈独立增益的 **90.9%** 来自被涨幅上限排除的仓位——这是一个**计数**，
  不依赖经济收益公式。

## 6. 追加规则

- **22**：**经济收益/滑点/费用的重放必须先从生产内核反解，并用引擎自己记录的数值验证**，
  而不是从"买入滑点 + 卖出滑点 + 费用"的直觉重新拼装。
  `entry_execution_price_usd` 已含买入滑点这一点，足以让一个看起来合理的公式错 5%，
  进而让一个结论的点估计移动两个数量级（−5.0U → +476.6U）。
  **验证方式**：拿引擎写下的 `pre_trigger.economic_return` 对分，要求**完全相等**而不是"接近"。
- **23**：**对抗性复核要交给独立的上下文去做，并且要复核者给"可独立验证的一手证据"，
  而不是只给结论。** 本轮子 Agent 之所以有用，是因为它给出了
  "用 `trigger_evidence_json` 对分，生产公式 1,265/1,300 完全相等"这种我能自己重跑的判据。
  只给结论的复核我不会采信，也不该采信。
