# ERR-20260904-002：Web 实时请求被客户端取消

## 1. 错误指纹与时间

- 07 错误编号：`3`
- 组件：`/api/live`
- 错误：`ConnectionAbortedError [WinError 10053]`
- 时间：2026-09-04 20:03:09（Asia/Shanghai），1 次。

## 2. 用户影响

无服务端数据损坏，无策略、行情或交易中断。用户切换页面、关闭标签页或浏览器开始下一轮 2 秒请求时，前一个 HTTP 连接可能被客户端取消。

## 3. 根因

旧 Web handler 在向已经关闭的 socket 写入 JSON 时抛出 `ConnectionAbortedError`，外层又把所有 `OSError` 统一记录成系统错误。客户端主动取消被错误归类为服务端故障。

## 4. 证据

- 该错误只有一次，发生在 `/api/live`。
- 同期 `/health`、Runtime 心跳和后续 `/api/live` 请求均正常。
- 没有对应 SQLite、计算或策略异常。

## 5. 代码修复

- JSON 和静态资源写响应时，正常结束 `BrokenPipeError`、`ConnectionResetError`、`ConnectionAbortedError`。
- 07 Web 记录入口再次排除这三类客户端断连，避免其他调用路径误报。
- 真实的 SQLite、计算、序列化和服务器 I/O 错误仍会进入07。

## 6. 验证

- 定向测试确认客户端断连不会新增07事件，真实高严重度错误的生命周期仍正常。
- 全量 Python 测试通过。
- 重启后的 8790 `/health` 正常，版本保持 v20。

## 7. 回退方法

如响应写入出现非客户端断连错误仍被吞掉，回退 `_send_json`、`_send_asset` 和 `record_web_error` 中的精确异常过滤；其他 API 和数据库无需变更。

## 8. 再次发生时的快速处理

1. 若错误仍是上述三类且只发生在响应写入，检查新代码是否已加载。
2. 若伴随 `/health` 失败或 SQLite 异常，按新的错误指纹另建事件，不得沿用本报告直接忽略。
3. 若大量客户端同时断连但健康正常，检查浏览器刷新、网络代理或页面导航，不重启交易 Runtime。

## 9. 遗留风险

客户端可以随时中断 HTTP 连接，这是正常网络行为。修复只消除错误监督误报，不会掩盖服务端生成响应之前发生的真实错误。
