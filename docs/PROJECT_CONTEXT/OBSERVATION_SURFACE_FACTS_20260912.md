# 观测面事实账：哪些入场档位真的可达（2026-09-12 实测）

本文件把"某个入场条件是否可达"从印象变成可复核事实。它存在的理由：本目标期间多次出现
"新臂注册成功、参数正确、测试通过，但永远不出样"的情况，逐代排查（并发度、合同差异、实现、
激活前沿、单币配额）后确认，**根因是某些入场档位在当前市场观测面根本不存在**——
不是策略写错，也不是过滤过严，而是引擎看到的池子分布里没有那一档。

## 1. 逐档实测（引擎机制就绪计数，按进程窗口）

| 入场档位 | 条件要点 | 实测就绪 | 判定 |
|---|---|---|---|
| `survivable_open_band` | 池龄30-180分钟、FDV/深度>20且≤1000、深度≥5000U、不下跌、深度不流失、买盘≥50% | 3–140（波动大但持续有） | **可达**（本族唯一稳定供给的带类入场） |
| `any_band`（第34波，各带并集） | 上表任一成立 | 与 `survivable_open_band` **完全相等**（如 32=32、72 vs 55） | 并集退化为单入口 → 其它带不供给 |
| `survivable_steady` | 池龄30-180分钟、FDV/深度1-20、深度≥5000U、不下跌、买盘≥50% | **0**（多个进程） | **不可达**（第30波4条镜像臂因此永不成交） |
| `survivable_band_mid` / `survivable_ste`…（1-20带放宽版） | FDV/深度1-20 | 0 | **不可达** |
| `mid_deep_band`（第32波） | 深度20k-100k、其余同上 | **0** | **不可达**（第32波2条臂因此无样本） |
| `deep_liq_band`（第31波） | 深度≥100k | **0** | **不可达**（复盘最优档，但观测不到） |

| `thin_depth_tier`（第28波） | 深度1000-5000U | **0** | **不可达** |

## 2. 由该事实推出的三条结论

1. **写销/深度的复盘结论无法在实时引擎直接检验**：复盘显示"≥100k 零写销、20–100k 写销 9.6%、
   5–20k 25.1%"，但这三档在实时观测面几乎不出现（本族安全带类机制就绪恒为 0），
   因此只能改在**可达的开放带**上间接检验（第31/32波臂已按此设计，并记录了不可达事实）。
2. **实验载体必须与市场供给匹配**：同一 A/B 合同先后换过四代载体（开放带并发2 → 开放带并发8 →
   多入口并集 → 非带类流量入口），只有第四代真正开始稳定成交（数分钟内 4→6 笔持仓）。
   这解释了本目标中期"实验长期 0 样本"的全部现象。
3. **"入场供给"本身是一项需要监控的运行时指标**：已把它纳入每轮核查（`flow_entry`/`any_band`/
   `survivable_open_band` 就绪计数），而不是靠等待。

## 3. 仍然有效的证据与开放问题

- **有效证据**（只读复盘，24小时/当前世代）：写销 216 笔 **100% 为 BSC**（31.5% 写销率、占净亏损 74%），
  Solana 0/1,599、Robinhood 0/184；净 −$626（PF 0.62）；有效独立样本仅 **≈159 个代币**。
- **有效否定证据**：放宽/延后止损**无平均收益**（延迟 60 分钟中位数 −$0.79、仅 34.2% 为正，
  回本率 1.7%）→ 方向是"容忍入场噪声"，不是拉长持有。
- **开放问题**：① 两对 A/B（长持有/宽追踪；死池前兆退出）的样本判定；
  ② 写销连续多个 60 分钟窗口为 0 是否可持续（6 小时窗口仍与三轮前持平）；
  ③ 同币拥挤（近 30 分钟 188 笔仅落在 9 个代币）——影子上限证据已足，等授权。

## 4. 追加（第 60–65 轮）：一次"伪异常"的完整排查链，以及标记覆盖率的真实约束

### 4.1 DC-1：新臂持仓"长期不平仓"的排查链（结论：伪异常）

现象：第 33–35 波共 12 条额外臂能开仓、能持续持有，但**全期 0 退出意图、0 平仓**，
而结构与它们相同的老臂正常产生退出意图。为解释该现象，依次提出并**逐条否定**了五个假设：

| 假设 | 检验方式 | 结果 |
|---|---|---|
| H1 评估未回写（`last_evaluated_at`/`pending_mark_id` 为空） | 代码检索两列的写入点 | 否定：两列是活跃字段，空白表示"当前无待结算事项" |
| H2 生命周期配额被更早的臂占用 | token 集合重叠度 | 否定：新 token 持续进入，无配额封锁 |
| H3 工程缺陷（`max_concurrent_positions=8` 使退出遍历排除这些臂） | `store.py` 全文检索该字段 | 否定：仅 3 处使用，全在**入场准入**（行 27193/27194/28469） |
| H4 标记稀疏导致评估稀缺 | 对比"这些臂持仓 token"与"正在正常平仓的 token"的标记密度 | 否定：两组标记密度**相同**（各 1 条/30 分钟） |
| H5 入场池身份与标记管线池身份不匹配 | cohort.pair_address vs market_marks.pair_address 全量比对 | 否定：**27/27 与 65/65 全部配对成功** |

**最终定性（时间序证据）**：这些持仓的 `opened_at` = 03:21:25，同 token+pool 在**开仓之后**
的首条标记出现在 03:29:38，而持仓年龄当时**仅 8.3 分钟** —— 四条臂的持有上限是 30/60/60/90 分钟，
**尚未到任何到期时点**，且期间只有一次评估机会。因此"6 持仓 / 0 退出意图 / 0 平仓"是
**入场批次同步 + 标记极端稀疏 + 持仓时间尚短**三者叠加的正常结果。

**方法论教训（写入本账以便复用）**：在短时间内反复读取同一批新仓的状态，会连续得到相同数字，
从而被误读为"停滞"或"缺陷"。正确的读取顺序是：**先确认观测窗口推进（如引擎帧计数增量），
再核对时间序（开仓时间 vs 标记时间）与持仓年龄，最后才解释状态**。

### 4.2 真实约束：标记覆盖率决定了退出规则的分辨率

实测（2026-09-12 03:29Z 窗口）：全系统近 **15 分钟仅写入 46 条标记**，而同期持有 **约 90 笔仓位**；
近 5 分钟 25 条标记、18 笔平仓。

推论（与历史复盘一致）：
- 需要**反复评估**才能触发的退出（追踪、深度衰减、信号衰减）**实际分辨率很低**；
- 只需要**一次**评估机会的退出（到期/max_hold）因此成为历史复盘中最大的正贡献族；
- 这解释了"退出机制看似丰富、实际主要由到期与止损主导"的现象。

据此新增第 36 波两条额外臂（纯新增，未改任何现有臂）：
`alpha149_dense_flow_v1`（入场 = `flow_entry` ∧ 本池已被引擎观测 ≥12 帧，1U/30 分钟）与
`alpha149_dense_flow_hold_v1`（同入场，1U/60 分钟，追踪 +50%/回撤 35%、−35% 兜底），
用于检验"在可被反复评估的池子上，宽追踪才有机会发挥作用"。

`alpha149_live_flow_revival_v1`、`alpha149_size_informed_flow_v1` 等**更早的臂**。
按**精确 arm_id** 全量重算，第 35 波四条臂的真实状态是：

|---|---|---|
| `alpha149_hold_flow_v1` | 7 | **0** |

| `alpha149_deadpool_flow_control_v1` | 7 | **0** |

因此 **DC-1 未结案**，4.1 节的"伪异常"结论予以撤回。

**同一现象的五次修正与共同根因**（登记以便不再重犯）：
1. 评估未回写（`last_evaluated_at` 空）→ 被代码检索否定；
2. 生命周期配额被占用 → 被 token 集合否定；

**共同根因：我用过宽或过窄的查询口径取样**（通配符过宽、快照时点、窗口未覆盖开仓批次），
而不是系统存在缺陷。**新的操作约束**（写入本账，后续必须遵守）：
- 涉及具体新臂时，一律用**精确 arm_id 列表**，禁用 `LIKE` 通配；
- 判断"是否有样本"用**按臂全量**或覆盖全部开仓批次的窗口，并先看该臂**最新开仓时间**；
- 任何"0 样本/停滞/缺陷"的结论，必须先用第二种独立口径复核后才能发布。

**仍然成立的干净对照（样本极小，仅作线索）**：开放带载体的对照臂结算 2/3（两笔均盈利），
而同批流量载体两侧合计结算 0/14 → 提示可能存在**载体级差异**，但 1–7 笔的样本量
**不足以支撑任何结论**；该对照需在样本累积后重做。


### 4.4 终局（第 71–73 轮）：DC-1 是"年龄假象"，附年龄受控对照

第 71 轮曾按机制类型比较结算转化率，得到"普通机制 99.6% vs 包装型多机制 17%"的 83 个百分点差距。
第 72 轮加入**年龄受控**后该差距消失：

| 分组 | 全期开仓/结算 | **近 60 分钟开仓/结算（同年龄段）** |
|---|---|---|
| 普通单一机制（267 臂） | 28,545 / 28,424（99.6%） | **300 / 215（71.7%）** |
| 包装型多机制（10 臂） | 46 / 3（6.5%） | **46 / 3（6.5%）** |

原因：包装型臂的持仓全部开于 03:19–03:31（读取时 DB 为 03:33），即**仅 2–14 分钟大**，
而持有上限为 30/60/90 分钟 —— 尚未到期。同期新建的**普通机制**臂表现相同：

| 臂（同期新建） | 机制 | 开仓 | 结算 |
|---|---|---|---|
| `long_hold_control_v1` | survivable_open_band | 3 | 2 |
| `deadpool_open_band_v1` | survivable_open_band | 2 | 0 |
| `hold_hi_open_band_v1` | survivable_open_band | 1 | 0 |
| `long_hold_steady_control_v1` | survivable_steady | 1 | 1 |
| `participant_breadth_v1` | participant_breadth | 1 | 1 |

**结论：DC-1 结案为非遗缺陷**——按同龄段对照，包装型多机制臂与其同期普通机制臂行为一致。

**新增操作约束（第 4 条口径纪律）**：比较"转化率/胜率/样本量"时**必须固定年龄段**
（全期数字会被成熟度污染：老臂的 99.6% 含数小时前的成熟仓位，新臂的全期即其全部历史）。

**五轮误判的完整清单**（供后续避免重复）：
1. 快照时点：只看得到刚开的批次 → 显示 0 结算；
2. `LIKE` 通配过宽：`alpha149_%flow%` 混入更早的 flow_fade / live_flow_revival / size_informed_flow；
3. 窗口不覆盖：180 分钟 `closed_at` 窗口未覆盖当时刚开的新仓；
4. 年龄未控制：全期转化率对比被成熟度污染（本节）；
5. 单点观察外推：以一次 8.3 分钟的持仓年龄推断"冻结"。


## 5. 帧准入与密集观测供给（第 79 轮实测，2026-09-12T03:40–03:50Z）

前四节回答"哪些入场层级可达"；本节回答**为什么会不可达**。三组独立测量指向同一个断点。

### 5.1 引擎占用不是容量所限，而是准入所限

| 量 | 值 |
|---|---|
| alpha149 引擎活跃池 | **67**（上限 `MAX_POOLS` = 512） |
| 本进程接受的帧 | 1,188 |
| 被拒帧（`invalid_or_unknown`） | 255 |

同一小时内 1,052 个代币有 >=2 次观测，引擎却只有 67 个池 → 排除容量与淘汰。
断点在 `dex_trajectory.Engine.accept` 的一行：

```python
if not valid or not str(row.get('provider','')).startswith('dexscreener') or ...
```

`alpha149.Engine.accept` 通过 `super()` 继承该门，因此**全部 136 条既有臂都继承"仅 dexscreener"**。

### 5.2 数据源构成（近 60 分钟，10,225 行快照，2,311 个代币）

| provider | 行 | 代币 | 行/代币 |
|---|---|---|---|
| `strategy-observer:dexscreener` | 4,467 | 273 | 16.4 |
| `geckoterminal` | 2,485 | 1,124 | 2.2 |
| `dexscreener` | 1,588 | 1,308 | 1.2 |
| `strategy-observer:geckoterminal` | 1,451 | 714 | 2.0 |

- 有 >=2 次观测的代币：**1,052**
- 其中拥有 >=2 帧 dexscreener 前缀的：**62（5.9%）**
- **完全没有** dexscreener 行的代币：**1,006（43.5%）**
- 前 10 个交易对占全部 8,000 个评估帧的 **32.3%**

注意 `strategy-observer:dexscreener` **不以** `dexscreener` 开头，因此今天同样被拒。

### 5.3 更深一层：机制需要 <=30 秒间隔的帧

`Engine.accept` 在相邻两次观测间隔 >30 秒时清空该池历史（`gap_reset`），而所有机制的窗口
最长 310 秒。因此该族只能判断**被密集观测**的代币。每小时实测：

| 数据源族 | 代币 | >=2 次观测 | 密集（>=3 帧且间隔 <=30 秒） |
|---|---|---|---|
| 任一数据源 | 2,311 | 1,062 | **33** |
| `dexscreener`（现行门） | 1,336 | 66 | **6** |
| `strategy-observer:dexscreener` | 277 | 226 | **28** |
| geckoterminal 族 | 1,095 | 831 | **0** |
| 非 dexscreener（第 38 波增量） | 1,292 | 995 | **30** |

**结论：0.57% 的代币级覆盖率是观测供给事实，不是可以调参的阈值。** 每小时只有约 33 个代币
密集到足以让该族任何成员判断，而现行门只放进其中约 6 个。第 37 波改池龄带却仍为 0，
正是因为这个原因——供给不在池龄上。

### 5.4 加密通道已饿死

`shared_batch_coverage.alpha149` 全进程累计：`eligible_batch` = **52**、`no_spare` = **51**、
`selected_extra` = **1**。`dex_http_capacity`：`max_inflight` 8、`active` 3、
`low_budget_cancellations_no_rotation` 11。为年轻池补帧的 spare-capacity 通道几乎拿不到地址位，
所以 5.3 的天花板无法靠策略侧调整抬高。

### 5.5 由此产生的操作约束

- 讨论覆盖率时，先区分**"被观测"（1,052/小时）**、**"密集到可判断"（33/小时）**、
  **"被准入"（6/小时）** 三个不同的量，不要把后者的低值当成阈值过严。
- 任何"提高覆盖率"的提案必须说明它抬高三者中的哪一个；只调阈值只能改变第三个。
- `geckoterminal` 族在 2.2 行/代币/小时的节奏下**不可能**形成密集轨迹（实测 0），
  它的价值是广度（发现与身份绑定），不是轨迹深度。
