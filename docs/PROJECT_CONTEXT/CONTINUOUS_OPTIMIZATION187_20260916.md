# 持续优化 187：热门案例复核、队列去重与分链策略实验

日期：2026-09-16

## 诊断结论

1. **热门案例覆盖仍有缺口，但总 API 配额不是当前主因。** 本轮约 81 个唯一地址中 65 个可在当前库定位。旧案例的高频断点是发现/准入后未在期限内得到安全确认或下一有效原池帧。当前 DexScreener 共享 HTTP 限额仍有余量，继续增加接口或盲目并发不能直接修复上游不可见与缺帧。
2. **计算入口存在可测的本地拥塞。** 部署前被动行情队列累计丢弃约 10,024/57,464 批（17.4%），等待 p95 约 12.6 秒。相同 token、原池和 observed_at 的缓存收据会在尚未处理时重复排队，随后重复解析、特征计算和数据库判断。
3. **最新同入口快/慢退出已经给出否定结果。** `core183_market_fast5_v1` 与 `core183_market_runner30_v1` 均约覆盖 152 个 Token，分别约 -452U 与 -967U；bootstrap 均值区间仍为负。单纯把首帧 market-visible 入口持有更久不能解决负期望。
4. **分链退出差异值得前向验证，但证据尚不支持上线结论。** trajectory144 同入口样本中，Solana runner 相对 fast 更强，BSC runner 更弱；优势集中于少数右尾赢家，必须以新资金臂严格前向复验。
5. **发现一个退出参数语义缺陷。** `policy.get("trailing_activate_return") or 99.0` 会把合法的 `0.0` 当成未配置，使“入场即启用 trailing”的实验无法表达。

## 已实施动作

- 在仍排队范围内按 `(canonical token, original pool, observed_at)` 合并完全相同的行情收据；feature-only 收据被普通行情覆盖时升级为普通处理。弹出、淘汰后立即释放索引，不改变已处理历史，不减少真实新帧。
- 增加 `coalesced_quotes` 与 `normal_takeovers` 运行指标，用于区分节省的重复工作与语义升级。
- 修复 0.0 trailing 激活阈值；仅 `None` 使用 99.0 的兼容默认值。
- 新增三条独立 Paper 臂，全部复用 trajectory144 已有信号和共享行情，不增加 API 调用：
  - `trajectory187_solana_runner_v1`：仅 Solana 的早期 impulse，保留 30 分钟 runner 退出。
  - `trajectory187_nonsol_fast_v1`：仅 BSC/Robinhood 的同类早期信号，保留 5 分钟快退。
  - `trajectory187_armed_runner_v1`：同 runner 入口/止损/期限，唯一退出变化是成本后 running return 曾达保本后启用 15% trailing。
- 根据成熟负期望证据暂停 10 个臂的新入场；历史、成交和已有仓位不改，已有仓位继续退出。

## 未改变的合同

- 买入前仍要求新鲜身份绑定原池和有效流动性；卖出前后仍检查原池。新鲜已知原池低于有效门槛时不买/核销剩余仓位，缺失、失败或陈旧证据不证明全亏。
- 默认共享池门槛 1000U，买卖滑点各 4%；未增加精确报价、深度冲击或策略专属网络请求。
- 未重置资金期、历史、账户或策略结果；Live 保持关闭。

## 后续监控与否证

- **底座：** 在相近负载窗口比较队列丢弃率、等待 p95、持仓/待卖 mark 年龄、发现至首帧以及第二/第三帧延迟。若持仓路径变差，优先减少低价值失败重试，不牺牲退出行情。
- **策略：** 按 Token 与链做孪生比较，报告净收益、核销率、洗出后恢复、右尾贡献和置信区间。三臂只使用激活后数据；若成熟后仍为负期望，暂停新入场而不继续调参追逐历史赢家。
