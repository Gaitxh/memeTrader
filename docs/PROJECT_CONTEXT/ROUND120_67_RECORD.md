## 1. 为什么要做

第 66 轮发现**一个**臂（`exit_ladder150_t10_v1`）在 30 分钟内被 `strategy_open_slot_limit` 拒绝
**1,609 次**。如果这能推广，那么统一的**每臂并发上限 8** 就是持仓数量的首要约束——
而那正是用户的核心抱怨（"开仓数量显著偏低"）。该上限是**用户授权的设置**，所以必须**量化它的代价**，不是改它。

同时这也牵出**第 28 轮的一个疑点**：它写"一个臂在 1000U/20U 下可持有 50 个并发仓位，而**观测到的最大值是 8**；
`max_open_positions = 0`（无限制）"，据此判定**并发不是约束**。
但"每策略上限 8"这条**用户指令的日期正是 2026-09-12**（同一天）——
**观测最大值恰好是 8，很可能就是上限在起作用，而不是"没有上限"。**

## 4. 第 28 轮：**结论对，证据不足**（据实更正）

- 第 28 轮**结论**（并发不是约束）**成立**——本轮用 490 万条判定证明它只占 1.27%。
- 但它用的**证据**（"观测最大值是 8"）**不足以支撑该结论**：
  8 恰好等于当天授权的上限，**观测到上限 ≠ 没有上限**。
- **正确的证据是本轮的分布**：仅 13 个臂曾触及、同时在顶的至多 3.3%。
- **并补上第 28 轮缺失的限定**：**并发上限对"退出载体"这一类是真实约束**
  （`widestop` 有 66.3% 的判定被它挡下），只是因为该类在舰队中占比小，所以不影响舰队级结论。

## 5. 主导约束已被量化：**等待不同的轨迹帧 = 51%**

`await_distinct_dex_trajectory_frame` 占**全部逐臂判定的 50.98%**——
**每两个判定里就有一个卡在"还没拿到足够多不同的观测帧"。**

这与第 65 轮的机制**完全吻合**：提供方每 **30.1 秒**才给一次新信息（仅 28.8% 的轮询有变化），
**三个不同帧需要 60–90 秒的连续观测**，而 120–300 秒的租约下只有 15.6%–43.9% 的序列能凑齐。

**于是"交易量为什么低"的完整机制链闭合了：**

```
用户看到的：开仓数量偏低
      ↑  51% 的逐臂判定卡在"等待不同的轨迹帧"
      ↑  因为三个不同帧需要 60–90 秒连续观测
      ↑  因为提供方每 ~30 秒才更新一次信息
      ↑  所以唯一的放大器是「同时能持有多少租约」= 观测槽位预算（用户决策项，边际产出 ≈4.7 窗口/槽位/小时）
```

**并且可以明确排除并发上限**：它只占 1.27%，只咬 13 个臂，且那 13 个都是按设计会饱和的退出载体。

## 6. 追加规则

- **46**：**"观测到的最大值恰好等于某个已配置的上限"时，不能把它当作"没有约束"的证据。**
  第 28 轮由"最大值是 8"推出"并发不是约束"，而 8 正是当天设定的上限；
  **要证明一个上限不构成约束，必须给出"有多少对象、多长时间在顶"的分布**，而不是一个最大值。
  （结论恰好正确，但这属于**运气**，不是证据。）
