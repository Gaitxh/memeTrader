## 1. 真正要解决的问题

目标不是增加策略、页面、审核或 Agent 数量，而是：已经买入的币能持续得到有效数据、及时判断并正确退出；资金与收益可信；系统能长期积累严格前向证据，并据此实现有区别的新策略，最终提高成本与风险后的盈利可能性。工程通过不等于经济有效，更不等于已经可以实盘。

问题分成四类，不混为一谈：

1. 系统缺陷：批次等待、采集失败、慢查询、单位/账本/时序错误、源码与运行版本漂移。
2. 策略问题：入场、退出、仓位规则与市场状态或成本不匹配。
3. 覆盖与资金问题：没采到、没完成判断、资金被占用或不足，不能统称策略无机会或无效。
4. 展示与交付问题：页面快但数据旧；“已修改/已测试/已推送/已部署”被混用，导致前后结果无法解释。

先修有证据的公共系统缺陷，再评价受影响策略。既不把所有亏损归咎于工程，也不把所有异常盈利当作策略优势。

## 4. 实施顺序、范围和交付标准

### 阶段 0：固定真实基线与可回溯代码检查点

- 只读核对当前权威状态、Git 分支/未提交差异、实际进程启动与发布标记、配置指定数据库和当前策略/账期边界。
- 将已有未部署修改分清：性能修复、资金候选、展示修复、无关用户工作；不能整体重启夹带尚未确认内容。
- 已有合适 Git 检查点直接复用；需补备份时在当前分支提交可说明的源代码检查点，记录 commit 和时间。必要时使用命名标签，不每次另建日期分支。
- 不上传密钥、钱包材料、私密聊天、config.json、数据库、日志及临时目录。不强推，不清理无关工作区。
- Git 是代码备份，不是假装数据库备份。涉及账期迁移前另做一次一致性数据备份，不能靠在线复制单个 SQLite 主文件遗漏 WAL。

交付：一张“当前在跑什么、待部署什么、可回到哪里”的清单。完成即进入核心修复，不展开全历史考古。

### 阶段 1：优先修复采集—判断—退出，以及已知核算缺口

性能主线：

1. 落实已有“每批有效行情返回 → 写入 → 只评估相关持仓”的修改，不等整轮慢请求。
2. 区分连接失败、上游限流、读取超时与本地排队；只修当前观察到的原因，不盲目加并发。
3. 在现有调度上调整退避占槽及低优先级任务竞争；遵守供应商限额，不用释放槽位绕过退避。
4. 待退出/确认优先，其次已有持仓；正常持仓保留公平服务。已持有的候选仓、仍有效的旧账期仓也不能饿死。
5. 同链同币共享请求、解码和基础特征；各策略独立判断和记账。行情原始采样、基础特征与策略行为不混同。
6. 对实测耗时的现金历史汇总、账户投影、同步 SQL、无变化写入局部优化；不在热循环反复扫全历史。
7. 研究、新闻、图表聚合低优先级；紧急退出或过载时可暂时停止研究，不再为每个 Token 建常驻 Agent。

核算主线：

- 定向检查已报告异常及正常买卖、分批退出、核销代表路径；涉及链/Token/池身份、数量、decimals、synthetic Paper 单位、价格单位、成本、现金、已实现/未实现收益。
- 基础派生特征也在范围内：时间窗、累计量与区间增量、成交加速度、买卖压力、年龄和运行高点等，优先覆盖当前在用且会影响买卖的部分。重叠窗口和缺失值不能制造伪信号。
- 双侧成本保持现有口径：买价上浮 4%、卖价下调 4%；额外费用按配置只入账一次。不能把这说成真实手续费固定 4%。
- 有效、匹配同一池的新鲜流动性数值低于 1 USD（包括明确的零值），剩余 Paper 仓位核销；原已卖出收入保留。字段缺失、超时、429、身份不明均不是零流动性。
- 连续成功查询确认缺池超过 60 秒的规则，与接口故障分开；中途恢复应中断缺失判定。检查信号前后独立采样和后续成交时间，不倒用未来价格。
- 缺失/陈旧估值不能标成实时零值，不能伪造 SELL；原始错误记录保留，修正与污染影响范围单列，正式统计采用一致口径。

交付：已知具体故障闭合，最小相关测试通过；可用新行情不再等待无关批次；受影响数据有明确边界。系统基础不存在“全面永无错误”的保证，只报告本阶段检查范围与未解决事实。

### 阶段 2：恢复有限资金，受控切换且不丢旧仓

本方案推荐的迁移设计，须在实施确认中明确切换时点：

- 当前仍运行的策略，各开启一次独立 1000U 有限资金账期，规则和策略 ID 不改。
- 当前旧账期停止新增入场，已有有效旧仓继续按原规则采集、判断、退出；回款留在旧账期。
- 按仓位创建时的账期归属记账，不能仅按 SELL 时间切分，否则旧仓回款会变成新账户的免费资产。
- 当前仍需服务的旧仓、新账期仓共用去重行情，全部计入实际监控负载。历史失败版本已经冻结的仓位不重新复活。
- 新账期从确认的真实切换点起只接收新信号，不把积压旧快照补成入场。
- 当前普通 Paper 计划单保持通常 20U；不足完整计划额及配置费用则记“资金不足”，不制造部分扣款却完整 20U 数量的成交。
- 资金满足后按规则再买，账户不自动补钱。已有仓的卖出不能被买入资金门阻断。
- 之后新增策略只给它自己建账户，不给已有策略再充值或再开账期。

先修旧仓退出，再切换；不能用重置后仓位暂少来冒充性能修复。如果旧仓负载仍不可承受，推迟新账期扩仓并报告，不通过强制清仓、伪造核销或静默放弃监控减负。

交付：现金/数量/成本/收益一致，新旧回款不混账，旧仓退出不断线，重复启动不重复注入 1000U，资金拒绝与策略拒绝分开。对新旧账期分别展示结果，不跨期硬连权益曲线。

### 阶段 3：必要数据源补强与多链覆盖

可与阶段 2 的非生产工作并行，但不让新源接入阻塞原有持仓修复。

- 保留 PumpPortal 新币/迁移、DexScreener 批量行情、GeckoTerminal 多链新池及已实现元数据链路。
- 优先复用 Pool/Vault accountSubscribe；核对池映射、链上账户解码、储备、槽位/时间和重连，先修可靠性再加派生指标。
- 不能因为有 WebSocket 就假定拿到了正确价格。储备事件若要影响退出，须有该金额的下一份新鲜可执行报价/明确等价 Paper 成交口径；不使用滞后的屏幕价造盈利。
- Solana、BSC、Robinhood 逐链列清：发现、行情、元数据、池映射、可用策略输入、成交能力、缺口。新旧策略尽可能复用各链等价输入；链特有证据缺失不能偷偷替换旧规则。
- 公共 API 无有效覆盖时明确缺口；不把测试网 token、同名 ticker、配置链名或一条历史样本当成完整主网能力。
- 对确实有价值的免费注册源，先确认额度、协议覆盖和测量收益，再请用户注册并本机保存 key；不打开自动收费。
- 新闻/社区 Agent 作为有时间戳、有有效期、低频共享的候选研究输入，不进入同步行情/卖出路径。

交付：真实覆盖和不足逐链可见；辅助源失败不拖垮主链，未配置 key 只阻塞对应能力。多链全面覆盖和所有 Live 链支持不能含糊归为一个“已完成”。

### 阶段 5：成熟度分层研究，并实现有区别的新策略

修复基础后即可推进，不等待全部 UI 美化或真实钱包入金。研究不等于授权实盘，也不因资金耗尽自动宣布策略淘汰。

先用一份有界报告说明：

- 策略来源、实际入场/退出/仓位规则、原始历史与继承策略区别、部署年龄和统计截止时间。
- 合格机会、BUY/SELL、完整往返、开放仓、已实现/未实现收益、胜率、单笔净收益分布、中位数、expectancy、盈亏比、profit factor。
- 最大回撤、尾部收益与损失、最大单笔、remove-best-1/3、利润集中度、持仓时间、资本占用、退出原因。
- 数据缺口/工程污染、资金不足、真正策略拒绝、未处理覆盖缺口；无法恢复的历史分母显示未知，不事后臆造 eligible。
- 同风格、共同前向窗口和独立 Token/市场事件比较；同币在几十个账户成交不能当几十份独立证据。
- 收益质量、风险稳健性、执行适配、资源效率、组合补充价值分别解释。评分若提供，公式/比较群体/版本可见，未充分样本不计零分。
- “样本不足”“工程受影响”“值得继续观察”“经济证据不利”“高度重复”等标签与理由；不由一个总分自动淘汰，不把负中位数或去掉赢家后亏损当所有尾部策略的硬判死刑。
- 工程样本可说明故障但不评价 alpha；研究发现用过的数据不再称独立验证结果。

候选方向与实际实现：

| 优先候选 | 要回答的问题与差异 |
| --- | --- |
| 静默后确认突破 | 复用已有 Flat Shadow；持续观察安静期，验证需求扩张，不在涨后回填突破起点 |
| 强势回撤后需求恢复 | 用当时运行高点、回撤、流动性和买卖变化研究二次入场，不把亏损老仓事后改名长期持有 |
| 同状态相对加速 | 在有界同期候选中比较同链/同龄/相近流动性对象，检验相对信号是否优于已有固定门槛 |
| 成功域互补组合 | 先找到 A/B 成本后的成功域与失败域，再冻结状态分类及 C 的规则，不机械拼接 |

- 上述是首批优先假设，不是已证实优势；有依据就实现若干真正不同的独立候选，不用已有 Runner/FirstMover/Mature 换名冒充新策略。
- 保留广泛多风格探索：早期小仓高风险、平衡与强确认、动量/突破、回撤/反转、趋势/非对称尾部、快速兑现、流动性/资金流、生命周期与分段仓位；不要求每类必造一个。
- 平价且无额外费用时，现有买价×1.04、卖价×0.96 模型往返约亏 7.69%，价格涨约 8.33% 才回本。1–2% 波动 scalping 不应在该口径下被当净盈利；数秒策略还须满足实际数据延迟。
- 规律性买卖先排除缓存/采样/重叠窗口假象，形成可解释的规律度、疑似机械支撑、撤出风险等观察特征，而不是直接标“骗子”。
- Agent 舆论辅助可成为独立候选：有时点证据、过期规则和预算，不能一句社区热度高就覆盖所有策略的既定退出。
- 每个可实施候选交付：问题与证据、冻结规则、新 ID、父策略差异、特征/成本/风险定义、最小测试、独立实际部署起点、后续自然观察。
- 缺证据则具体写缺什么，保留 Shadow；不会为了“若干”强行制造参数爆炸，也不会已具备依据却无限停在写报告。

恢复两小时循环前：核实并更新原任务的 1000U、MAE/MFE 取消、append-only、后台优先等规则；保留周期与通知偏好，不创建重复任务。正常时进行复盘/候选实现，过载时先修系统并可暂停研发。本轮仅计划，不启动循环。

交付：有证据的独立新策略真正接入现有 Registry/Runtime/UI，从部署后接收新数据；报告明确研究样本、模拟和自然前向的区别。持续研究不是一次性“全部完成”。

### 阶段 6：Live 执行边界与上线准备（不阻塞 Paper 研究）

- 保留用户“共用策略逻辑、Live 接收信号执行”的方向，不另写一套策略。
- 当前 Paper 成交镜像存在资金耦合：Paper 没钱可能不产生 BUY，而有钱的 Live 钱包也收不到意图。推荐最小分离为同源策略意图、各自资金与实际持仓；Live 启用前必须解决这个具体问题。
- Live 买入金额不超过 20U 及策略自身上限，按实际可用余额、已占用额度、精度和最低可执行额缩量；金额为空或无执行路线不买。
- 原生 gas 独立保留（按实际链与已持仓退出需要），不能从 USDC 留 4% 就宣称卖出费用有保障。
- 数量相关新鲜报价、签名发送、确认、幂等和实际余额对账完整验证；不拿 synthetic Paper raw amount 发送真实交易。
- Paper/Live 入场价和持仓不同，同一规则未必同一时间卖出。不能照搬 Paper 虚构成交或把 Paper 全损当链上已卖出。
- 钱包暂停新入场与继续退出分清；确认不明不盲目重复下单。
- 已在聊天曝光的测试私钥不作为未来生产钱包；密钥本机加密且不回显。读余额/模拟验证与真实成交分别说明。

交付分级：接口/工程测试通过、持续 Paper 可用、真实小额成交核验分别报告。实际使用资金需用户独立确认；本次方案不授权广播交易。

## 5. 性能验收：数值必须说明口径

| 观察项 | 如何测、如何判断 |
| --- | --- |
| 新币发现 | 事件到本地接收/入库延迟，轮询源的成功间隔与覆盖；没新事件不等于掉线 |
| 持仓采集 | 相邻成功接收间隔、当前数据年龄、失败率、最久未服务，按链/优先级分层 |
| 内部处理 | 排队、请求、写库、特征/判断分段；有效行情入库到相关退出评估首轮工程目标 P95≤1秒 |
| 卖出 | 触发到后帧确认、到成交/确认各耗时；报告未完成数量与最老待处理，不只统计成功单 |
| 展示 | 页面生成与底层数据年龄分开；轻量总览冷/热 API 的 P95<1秒为工程目标 |
| 资源 | 事件循环滞后、CPU、RSS/系统可用内存、SQLite写入/锁/WAL增长与checkpoint耗时、磁盘余量 |
| 容量 | 去重币/实际池数、策略仓位投影量、新增/退出速度；不把账户数当唯一负载指标 |

首轮在修复前后相近负载下做短窗口观测（通常约10–15分钟，低事件量则明确样本不足），不拿重置后的低负载结果与原高负载直接比较。持续自然运行阶段继续显示真实覆盖，不将一次短测当长期稳定证明。

不承诺数千个币全量每秒成功更新。当前本地0.25秒请求起始间隔对应理想240请求/分钟，满30币批为7200币次；还需扣除失败、其他任务、分链不足满批、网络与计算。官方限额不等于实际可用吞吐。

不通过调大行情新鲜度窗口、排除失败对象、只统计已完成卖出，来制造性能达标。相同负载下有明显可复现退化且局部优化无效，先回退引起退化的代码，不回滚自然账本。需要限制新增负载时另报依据，旧仓不停止服务。

存储优化先减少重复读取/无变化写入和过密显示快照；保护真实交易与因果证据，不擅自删库、截断历史、在线重型 VACUUM 或强制频繁 checkpoint。内存优化针对实际常驻缓存/结果集，不因账本大就假定 OOM。
