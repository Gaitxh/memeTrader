# 2026-09-12 全面审查第 14 轮（续）：安全带供应之谜被逐条件计数解开（wave 21）

## 1. 谜题

第 13 轮发现：同一引擎里 `survivable_band_deep`（FDV/深度≥5、无上限）触发 75 次，而最安全的 `survivable_core`（FDV/深度 1–20）仅 5 次。已排除两层解释：
- **深度下限**（wave 19 把下限从 5000/10000U 放宽到 3000U，触发次数不变：2 vs 2）；
- **区间稀缺**（本轮 154,381 帧联合分布显示，池龄 30–180 分钟内 FDV/深度 1–20 占 **51.9%**，>20 仅 21.4%）。

## 2. 定位：加装逐条件计数器（仅仪表，不影响交易）

在 `Engine.signals_for` 中、**在 `prev` 已附加之后**加入有界计数器（首版放错位置——在 `prev` 附加之前——得到 0/0 的假象，已修正并在文档中保留这一过程）。实测 621 帧：

| 条件 | 通过率 |
|---|---|
| 有前一帧（同池≥2帧） | 92.8% |
| 池龄 30–180 分钟 | 63.9% |
| FDV/深度已知 | 100% |
| FDV/深度 1–20 | 48.6% |
| FDV/深度 ≥5 | **63.0%** |
| 深度 ≥5000U / ≥10000U | 97.7% / 95.8% |
| **严格上涨（>）** | **2.7%** |
| **不下跌（≥）** | **91.1%** |
| 深度不流失（≥前帧98%） | 92.4% |
| 买盘≥50% | 66.8% |
| **core 链（池龄+1–20+深度≥5000）** | **16.1%** |
| **deep 链（池龄+≥5+深度≥10000）** | **62.8%** |

**结论**：真正的瓶颈是**"当前帧必须严格上涨"**——引擎连续帧绝大多数是**同一价格的重复报价**（≥ 通过 91.1%，> 只通过 2.7%）。此外安全带区间再叠加 3.9 倍差距（16.1% vs 62.8%）。两者相乘正好解释观测到的 5 vs 22–75。

## 3. 修复（wave 21，1 条全新 ID）

关键认识：**"严格上涨"是从突破族继承来的条件，而写销风险实测来自池子的 FDV/深度带与池龄，不来自该帧的斜率**。因此新增机制 `survivable_steady`：与 `survivable_core` 同样的池子条件（池龄 30–180 分钟、FDV/深度 1–20、深度≥5000U、深度不流失、买盘≥50%），只把"严格上涨"改为**"不下跌"**。

| arm_id | 入场 | 退出 | 投注额 |
|---|---|---|---|
| `alpha149_survivable_steady_v1` | **`survivable_steady`** | 实测最强短兑现合同（−20%/追踪30→15/30 分钟） | 1U |

**加载后实测（584 帧）**：

| 机制 | ready |
|---|---|
| `survivable_core`（严格上涨） | **1** |
| **`survivable_steady`（不下跌）** | **43** |
| `survivable_band_deep` | 18 |

→ **安全带的可达供应放大约 43 倍**（事前预测 34 倍），并且该臂已在加载后数分钟内出信号。

- 注册：append-only，`policy_additions` 255 → **256**，账本/资金周期/激活前沿不变；22:47Z 前后加载。
- 单测 **45 项 alpha149 + 2 项 whipsaw 全 PASS**（新增：持平帧满足 steady 但不满足 core；上涨帧两者都满足；下跌帧两者都不满足；带/池龄/深度/买盘/深度流失条件在 steady 上仍全部生效；父臂合同与 2U 投注额不变）。

## 4. 本轮完整成果
1. **wave 20**：把矩阵中胜出的止损时点合同推广到两个其他入场族（`age_rate_acceleration`、`survivable_band_deep`）。
2. **诊断**：安全带供应之谜解开——**严格上涨条件只通过 2.7% 的帧**，安全带因此长期低产；这是本会话继"家族 depth 取值"与"信号循环嵌套"之后的**第三个真实可达性缺陷**（前两个是崩溃/异常级，这个是供应级）。
3. **wave 21**：以"不下跌"替代"严格上涨"，实测放大 43 倍，安全带终于可以按其设计频率交易。

## 5. 诚实边界与下一轮（15/256）

1. `survivable_steady` 放宽的是**帧斜率**而非池子条件；持平的帧是否与上涨帧有相同的事后表现，尚无前向证据——这正是该臂与 `survivable_core` 的同池对照要回答的。
2. 逐条件计数器的首版放错位置（在 `prev` 附加前）曾给出 0/0 的误导结果，已修正；此类仪表代码本身需要位置正确才能可信。
3. 下一轮：① 观察 steady 臂的成交与退出质量；② 若"不下跌"版表现不劣于"严格上涨"版，则把它作为安全带族的标准帧条件（以新臂形式推广）；③ 继续矩阵样本累积。
