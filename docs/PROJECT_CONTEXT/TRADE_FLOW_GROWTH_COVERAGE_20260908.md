# 交易量下降：成长阶段行情覆盖断档与修复（2026-09-08）

## 结论与证据

这次下降有可定位的供给端原因，不能仅用“市场机会少”或“系统不够快”解释。北京时间07、08、09、10点完整小时BUY为700、326、268、234笔。这是多账户Paper记录，同一币在不同账户的买入分别计数。

1. **新币发现持续，成长阶段数据消失。** UTC23:00、23:15、23:30、23:45四个15分钟窗口首次本地发现分别511、569、509、530个。BSC Gecko共享行情仍每窗口约180—200帧；但大于15分钟池龄的帧由18、23变为0，此后至UTC03:15每个完整窗口都是0。
2. **新池第一页不能承担生命周期跟进。** Gecko请求 `new_pools` 第一页。新发行密集后，页内最大池龄从UTC23:15窗口的1254秒降为23:30窗口的665秒，最新完整03:00窗口仍只有615秒。币长到15分钟以前就离开该页。成功补全又被记为终态，普通补全队列排除 `hydrated`，因此没有独立共享复查补上这个阶段。
3. **26个flow_burst账户有钱但没输入。** UTC21、22、23分别接收2、8、10个共享flow机会，之后连该类别输入都没有。20个机会中19个来自约15—21分钟龄的BSC Gecko池。26个账户可用现金约564.62—675.71U、没有持仓，并非余额或仓位上限。原有独立观察实验的行情有意不向旧策略提供额外机会，该隔离保持。
4. **另有真实资金不足及错误归因。** 四个仍匹配共享broad_launch的账户只有8.0821或9.9427U，不够原20U下单。除此以外，“没有匹配的启用策略”也被错误标为现金不足：UTC00/01/02分别734/670/570条。这部分只修正今后的拒绝原因，不改历史、补款或降低下单条件。
5. **当前判断没有堵塞。** 取证时共享游标没有未消费合格快照，没有待执行BUY意图；信号到判断的观察年龄中位约0.35—0.48秒、P95约0.94—1.16秒。持仓刷新中位约1.32秒，入场批计算约11.68毫秒。

## 本次实现

- 复用现有 `token_detail_hydration`、5秒调度和Dex批量通道，每轮最多10个目标，最多2个名额用于成长阶段跟进，其余保留给首次补全/原有重试；没有到期跟进时普通队列可以使用全部名额。不同链轮换，链内按最早到期顺序处理。
- 仅由部署后真实收到的普通发现/补全行情安排跟进。要求可用、时序正确、身份一致的价格和流动性，达到当前共享流动性下限；首次跟进不早于池龄901秒和当前时间60秒后的较晚者。随后最多每60秒到期一次；实际服务间隔受队列和来源限制，不声称每个币每分钟都能刷新。
- 使用 `fresh=True`、原共享退避和持仓并发预留。新快照沿普通持久化路径进入共享判断，保留上游观察时间与原有策略事件/冷却规则，不移除 `strategy-observer:*` 隔离。
- 给可变补全队列增加一个可空的 `followup_until` 截止字段。失败仍记录 `no_pair/error`，保留跟进身份，5分钟后在同一小配额内重试；超过截止时间不请求，返回时已过期也不作为该跟进的新共享帧。截止为已观察池创建时间加6小时。旧普通队列行默认空，不回填历史特征。
- 跟进曝光标记 `market_followup`，不计首次发现。没有匹配策略改记 `no_active_matching_entry_policy`，界面分别解释“未匹配”和“资金不足”。

## 计算与资源复核

当前主要读取均走索引，抽查单次约0.02—0.31毫秒。共享观察队列丢弃计数的两个相隔62秒截面一致，不能把旧累计丢弃当成当前仍在丢数据，也不据此扩大计算预算。

每币重建有效策略定义仍约10毫秒，是潜在优化点；复用必须同步处理账户暂停、策略追加和执行设置变化。本轮没有引入新的定义缓存，先修复直接导致输入消失的覆盖断档。已有持仓优先、跨链并行、小批补全及行情唤醒保持。

## 限制

这是有界覆盖修复，不是全链全生命周期扫描。最多2个跟进名额不能保证所有候选持续一分钟刷新；上游缺池、缓存和限流仍可能导致无行情。新采集范围与部署前不同，前后成交数量不能直接当作Alpha或市场热度的因果对照。增加观察机会不保证增加利润；原池缺口、真实亏损和账户资金限制仍需如实呈现。
