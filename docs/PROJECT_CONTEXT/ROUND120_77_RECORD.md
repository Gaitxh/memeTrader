# 第 77 轮记录：最大亏损路径的解剖——池子在"高点"时是健康的，但 78% 的仓位从未触及自己那条臂的追踪激活线

> ## ⚠️ 第 79 轮限定：§2 那条"可捕获窗口存在"的推论**从这份数据里判不出来**
>
> 第 79 轮在做因果检验时发现 **mark 流在核销前是冻结的**：
> 1,019 个可用案例里 **60.1% 的仓位最后 5 个 mark 价格与流动性完全不变**，
> **不同价格数 / mark 数 p50 只有 0.24**（即约 76% 是重复值），
> 而且 **75.4% 的核销仓位最后一个 mark 仍在下限之上**——
> **核销所依据的证据从未进入 mark 历史。**
>
> **因此**：§2 的"966/966 在记下高点的 mark 上流动性健康"这句**测量本身没错**，
> 但它实际测的是"**监控开始时的池子状态**"（因为 high 那条 mark 往往就是最后一条冻结的 mark），
> **不是**"浮盈时刻的池子状态"。
> **能确定的**：记录显示监控开始时池子健康、且**没有任何显示下跌的观测**。
> **不能确定的**：市场上是否真的存在过一个"既有浮盈、池子又活着"的时刻。
>
> **本记录中不受影响、继续成立的部分**：§1 的形状统计、§4 的机制链、以及**§3 的核心结论——
> 78% 的核销仓位从未触及自己那条臂的追踪激活线**（这一条比较的是引擎记录的
> `highest_signal_price_usd` 与各臂的 `trailing_activate_return`，**不依赖 mark 序列**）。

## 0. 一句话结论

1. 第 76 轮测出：**1,150 个以 `dex_pool_liquidity_below_configured_floor` 结束的仓位，
   中位峰值 +0.171**——它们涨过，然后归零。本轮把这条路径拆开。
2. **池子在"高点"时是健康的。** 966 个可追溯高点的仓位里，
   **966 个（100%）在触及高点的那一刻流动性都 ≥ 1,000 USD 下限**，中位 **40,367 USD**，
   最低 9,168 USD。**没有一个是在池子已经垂死时创下高点的。**
3. **引擎看着它跌。** 这些仓位在生期间的中位 mark 数是 **45 个**（p75 61、p90 84）。
4. **从高点到核销的中位时间只有 3.1 分钟**（p75 5.1、p90 5.6 分钟）；28.6% 超过 5 分钟。
5. **：78.0% 的核销仓位从未触及自己那条臂的追踪激活线。**
   - 峰值达到本臂 `trailing_activate_return` 的：**253 个（22.0%）**
   - 未达到的：**897 个（78.0%）**
   - 各臂的激活线分布在 **0.20 – 0.50**，而核销仓位的**中位峰值只有 0.15–0.23**。
6. **∴ 对这些仓位而言，追踪退出"没触发"不是失误，而是构造上不可能触发。**
   这是一个**覆盖缺口**，不是执行缺陷。

## 2. 决定性检验：高点那一刻池子还活着吗

引擎**只记录 running high 的数值，不记录它的时间**，所以高点时刻由该 token 自己的 mark 序列还原
（取第一个价格达到记录高点 99% 的 mark，作为高点时刻的下界）。

| 高点时刻的池子流动性 | 数量 | 占比 |
|---|---|---|
| **≥ 1,000 USD 下限（池子健康）** | **966** | **100.0%** |
| < 下限（池子已在垂死） | **0** | **0.0%** |
| 该 mark 无流动性字段 | 0 | 0.0% |

健康池子那一组的流动性：**中位 40,367 USD、最低 9,168、最高 153,048**；
峰值中位 **+0.165**、最高 **+1.489**。

**∴ 不存在"高点与死亡同时发生"的解释。确实存在一个既有可观浮盈、池子又健康、
且持续了数分钟的时刻窗口。**

**从高点到核销的间隔**：p10 0.5 / p25 1.0 / **p50 3.1** / p75 5.1 / p90 5.6 分钟；
**28.6% 超过 5 分钟，2.7% 超过 15 分钟。**

## 4. 完整的机制陈述

```
1,150 个仓位以「池子流动性跌破下限」核销
  ↑  其中 85.7% 曾经盈利，中位峰值 +17.1%
  ↑  而在触及高点的那一刻，池子流动性 100% 仍在下限之上（中位 40,367 USD）
  ↑  引擎在生期间持有中位 45 个 mark —— 它看着这个过程
  ↑  高点与核销之间中位只有 3.1 分钟
  ↑  但 78% 的仓位从未触及自己那条臂的 tracking 激活线（各臂 0.20–0.50，中位峰值 0.15–0.23）
  ↑  ∴ 追踪退出「没触发」是覆盖缺口，不是执行失误
  ↑  同时硬止损在各臂设为 −0.20 到 −0.90 —— 而池子死亡在到达这些价位之前就发生了
```

**这解释了第 76 轮那个 −436.6% 的捕获率**：
核销路径**没有可用的退出机制去捕获那 +17%**——
追踪线太高（78% 够不到），硬止损太深（池子先死），止盈档只覆盖 90 个仓位。

## 5. 这证明了什么、**没有**证明什么

**证明了**（全部为对已实现行为的描述）：
1. 核销仓位在高点时刻的池子是**健康的**（966/966）；
2. 引擎**有充分观测**（中位 45 个 mark）却没有退出；
3. 高点到核销**只隔中位 3.1 分钟**；
4. **78% 的仓位从未触及本臂的追踪激活线**，所以对它们而言追踪退出构造上不可能触发；
5. 覆盖缺口的具体形状：**激活线（0.20–0.50）系统性地高于这些池子的实际峰值（0.15–0.23）**。

**没有证明**：改任何档位就能捕获那部分浮盈。
- running high **只有被超越之后才知道**；实时规则看到的是一帧一帧的价格。
- 池子死亡的速度（中位 3.1 分钟）意味着任何"等确认再退"的规则都可能来不及。
- 第 43 轮已经证明：在**保留账簿**上，止盈的样本内边际价值约为 0
  （它救的全是被 run-up 上限排除掉的仓位）。

**∴ 本轮不提出任何参数改动、不新建模块。**
上面每一条都是**描述**，而"该改成什么"必须走用户规定的形式：
**额外策略模块 + 自己的前向证据**。

## 6. 对用户 mandate 的对应关系

用户要求"设计更稳健、更复杂的退出机制（波动率自适应止损、分批止盈、信号衰减退出、
时间止损、结构确认退出等多维度组合）"。**本轮的测量正好指出这个组合应该覆盖哪个空白：**

| 用户列举的维度 | 本轮实测的相关性 |
|---|---|
| 分批止盈 | 只有 90/1,150 个核销仓位所在臂带档位；**覆盖不足** |
| 信号衰减退出 | **未被任何档位覆盖**：78% 的仓位峰值在 0.15–0.23，而最低激活线是 0.20 |
| 时间止损 | 生期间中位仅 8.8 分钟，**时间止损大概来不及**（但这是待验证的推断） |
| 波动率自适应止损 | 硬止损设 −0.20 至 −0.90，**而池子死亡先于这些价位发生** |
| 结构确认退出 | 池子流动性本身就是结构指标，且**它在高点是健康的**，随后 3.1 分钟内崩溃 |

**最值得作为额外模块去验证的空白是"低阈值激活"**：
现行激活线 0.20–0.50 与这些池子的实际峰值（0.15–0.23）**几乎不相交**。
一个激活线更低的载体臂可以覆盖这一整类，
**而这正是"额外策略模块"的形式**（第 58 轮的 `exit_ladder150` 是同一思路的先例）。
**本轮只指出空白与形式，不设计、不部署。**
