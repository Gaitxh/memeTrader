# 持仓网络等待造成后台饥饿：P0-A 修复

响应 `C2C-20260908-DORMANCY-SCHEDULER-BACKPRESSURE-P0-04`。本轮只修复已经定位的全局调度阻塞；early_impulse 与既有策略继续自然 Paper。

## 原因与边界

`chain_meme_market_marks_once` 在整个持仓刷新开始时清除全局 idle 事件，直到所有网络请求、落库和退出判断结束才恢复。候选取数、资料补全、被动分析和低优先 DEX 槽位都等待这个事件。因此即使已有总计 8 个请求槽位、低优先最多 5 个的限制，持仓请求等待网络时后台仍不能使用空余容量。

15:32 部署前，持仓轮次耗时 p50/P95 为 1.389/3.529 秒，实际间隔 1.599/3.932 秒；2 秒被动观察轮次耗时 0.951/4.931 秒。15:22 持久化计数已有 56,697 丢弃批次、462,085 丢弃报价，均是历史累计，不能当成本轮或每分钟损失。独立 Agent 复核了相同代码因果链。

这证实一种持续运行饥饿来源，不能仅凭它认定所有策略沉寂、全部亏损或重启激活都已解释。

## 实施

- 移除持仓刷新函数覆盖整个网络阶段的 idle 清除/恢复。继续使用原有 8/5 信号量、3 个持仓预留槽位、共享限流退避及超时。
- 保留每批持仓响应立即落库与退出计算。这一段没有 await，后台协程不会插入这段计算；原有后台逐币让位继续保留。
- 在现有运行计时载荷增加固定大小的被动队列摘要：本进程入队、处理、丢批/丢报价、当前/最大深度、最老入队时间及最近 120 个已出队批次等待时间的 p50/P95。等待时间从本地行情收到至分析出队，包含调度等待，不冒充上游数据年龄。计数明确为本进程累计，不替换原资金期历史计数。
- 没有新增数据库表、后台任务、依赖、请求额度或策略参数。保留 16 批 FIFO 的原语义；身份合并和观察名额调整不混入 P0-A。
