## 2. 我自己犯的两个探针缺陷（这是本轮的主要教训）

### 缺陷 A：锚点用错——用了成交快照而不是决策快照

`store.py:27955-27957` 用**决策快照**判定：

```python
floor_rejection = activity_floor150.reject_reason(arm, snapshot)          # snapshot = 正在被决策的那一帧
if floor_rejection is None:
    floor_rejection = runup_floor150.reject_reason(arm, snapshot, history)
```

而 r41 第一版读的是 `positions.entry_snapshot_id`（**更晚**的、用于成交的下一帧）和
`entry_execution_price_usd`。后者含 4% 买入滑点，于是涨幅被**系统性抬高约 4 个百分点**——
15% 上限下，真实涨幅只要超过 ~10.6% 就会被误判为违规。

实测对照（`r41b` 侧栏）：15 个 r15 仓位里有 12 个 `runup_ex%` 恰好等于 4.00%，即纯滑点。

**修正**：锚点改为 `chain_meme_trader_v6_cohorts.source_snapshot_id` + `decided_at`。

### 缺陷 B：窗口少了池子身份过滤——代币可以有**两个池**

`store.py:27662-27673` 的生产窗口按 `canonical_token_address(chain, pair.pairAddress)` 过滤，
只保留**决策自己那个池**。我的 SQL 只过滤了 token + cohort_observer + 时间窗。

`solana:L2mVBBTJZ...` 在**同一时刻** `2026-09-12T22:09:20.465748Z` 被观测到两个池：

| id | 池地址 | price_usd |
|---|---|---|
| 46377 | `4U8iA9GSbeqzvVVnykEqG2…` | **1.0886e-05** |
| 46378 | `3i2C1MQ5aSBfa5v6LjPpSU…` | **3.7230e-03** |

两者相差 **342×**。缺了池过滤，我的 `history[0]` 取到那个 1.0886e-05 的陈旧池，
算出 **+35,431%** 的涨幅 → 误报违规。生产取到 3.7230e-03 → 涨幅 **+3.8944%** → 放行，与它自己记录的
`cohort_frozen_opportunity_ready` 完全一致。

**这个池过滤是承重的，不是装饰。** 去掉它，涨幅上限臂会对几乎一切入场误判为"已暴涨"而拒绝。

## 4. 顺带查实并**证伪**的一个价格完整性假设

起因：r41i 显示最差的 20 分钟窗口价差高达 **319,016×**，且低端价格在不同代币间反复落在
~1.8e-06 附近，像是某个"默认值/错字段"。假设：**某些帧把 `priceNative` 填进了 `price_usd`**
（USD 价被低估约报价币的美元价倍数）。判别式 `price_usd / priceNative` 应当等于**报价币自己的美元价**。

**按报价币分类后假设被干净证伪**（`r41l`，37,141 帧）：

| 报价币类别 | 帧数 | ratio<2 | 中位 ratio |
|---|---|---|---|
| 波动报价（SOL/WBNB…），ratio **应**为报价币美元价 | 28,156 | **11 (0.04%)** | 726.2 |
| 稳定币报价（USDT/USDC/USDG…），ratio≈1 是**正确的** | 3,960 | 3,952 (99.80%) | 1.0 |

我最初标记的 6,477 帧"错字段特征"里，**只有 11 帧是真的**——其余全是稳定币报价池的**正常**表现。
`bsc:0x0c886587…`（161 个写下线、入场价 0.0002384）的报价币是 **USDT**，`priceNative ≈ priceUsd` 完全正确；
那 161 个仓位的 −3,220U 是**池死亡**这条已知损失通道（r36/r39），不是价格缺陷。
> 教训：任何派生指标在引用前必须对**底层量**做分解；这次的底层量是"报价币是谁"。

**残余**：15 帧（占 37,241 帧的 **0.04%**，全部来自 geckoterminal，价格低至 1e-21）在波动报价池上
内部不一致——典型的**已抽干池**残留价。逐项追踪其是否触达资金：

- 作为**入场快照**：0
- 作为**决策快照**（cohort.source_snapshot_id）：0
- 被 `chain_meme_trader_marks.snapshot_id` 引用：0
- 其价格出现在决策所依据的 `chain_meme_trader_market_mark_history`：0

**残余影响为零。列为监控项，不做改动**；falsifier = 出现任一帧被用作决策/标记快照。

## 5. 顺带查实：多池代币的普遍性

`r41g`，按**规范化**地址分组（`canonical_token_address`，EVM 小写、Solana 原样）：

- 观测到的代币 5,416 个，其中 **271 个（5.0%）**在 ≥2 个池上被观测到。
- 跨池均价分歧：<1.5× 188 个；1.5–10× 64 个；10–100× 5 个；**≥100× 14 个**。
- **原始字符串分组会造假**：219 行是同一 EVM 地址仅 **EIP-55 大小写不同**。
  按原始串分组会把一个池劈成两个"池"，并捏造出 177 万倍的"跨池分歧"。
  > 教训：对一个 group-by 的**身份键**先确认它的规范化规则，再相信分组结果。

## 6. 本轮确立的可复用规则（追加到既有 8 条之后）

9. **审计一个已部署的机制时，锚点必须取该机制自己用的那一帧**——不是最近的一帧，也不是成交帧。
   成交价与决策价之间隔着滑点，量级足以把合规判成违规。
10. **窗口类统计必须先按身份键（池/交易对）过滤，再取极值**；否则一个陈旧的第二池就能捏造出任意倍数。
11. **分组统计前先验证身份键的规范化**：EIP-55 大小写差异会把一个池算成两个。
12. **一个派生判别式在引用前必须对底层量分解**：`ratio≈1` 在稳定币报价池上是**正确**的，
    不分解就会把 99.9% 的正常帧报成缺陷。
13. **能查到生产自己的判定时，就不要用重算去替代它**；重算只用于解释分歧，不用于定罪。
