# 第 81 轮记录：窗口不是问题——池子中位健康 493 秒、期间 45 次观测、且**所有浮盈都发生在池子健康期间**

日期：2026-09-13
前置：`ROUND120_80_RECORD.md`
本轮性质：**把"金狗拿不住"追到可设计的层面，并给出一个参数不敏感的机制结论。**
没有改任何策略、阈值或运行时行为。

---

## 0. 一句话结论

1. 第 80 轮关闭了核销路径（标的真死、机制正确），但留下用户 mandate 的核心问题：
   **有没有一个"池子还活着、仓位还有浮盈"的时刻，让规则可以卖出？**
2. **有，而且窗口很大。** 实测 976 个核销仓位：

   | 量 | 实测 |
   |---|---|
   | **池子处于下限之上的时长** | p25 235 秒 / **p50 493 秒** / p75 696 秒 / p90 934 秒 |
   | 健康时长 ≥ 300 秒 | **72.2%** |
   | **健康期间的已知流动性 mark 数** | p25 22 / **p50 45** / p75 64 |
   | 健康 mark 数 ≥ 5 | **99.3%** |
3. **所有浮盈都发生在池子健康期间。** "健康期间达到的峰值"与"整个生期的峰值"**完全相同**
   （p50 都是 **+0.1647**；+5%/+10%/+25% 的触达率逐项一致：71.6/71.8、57.0/57.0、26.1/26.1）。
   **∴ 这些仓位曾经拥有过的每一分浮盈，都是在池子可交易时被看到的。**
4. **所以瓶颈不在数据可得性，而在退出规则拿到这 45 次观测之后做了什么。**
5. **因果检验（限定在健康区间内，遵守因果规则）：**

   | 规则 | 均值 | 中位 | 合计 | 相对实际 |
   |---|---|---|---|---|
   | **实际（粉尘核销）** | −0.970 | −1.000 | **−944.2** | — |
   | 回撤 10% | +0.109 | +0.091 | +106.5 | **+1050.7** |
   | 回撤 25% | +0.123 | +0.094 | +119.9 | +1064.1 |
   | 回撤 50% | +0.124 | +0.091 | +120.3 | +1064.4 |

6. **最关键的发现：回撤参数几乎无关紧要**（10%→50% 全部落在 +106 到 +120 之间，均值 +0.109~+0.124）。
   **7. 决定性的区别是"是否武装"，不是"回撤多深"。**
   按各臂**自己的**合约（先涨到 0.20–0.60 才武装）模拟，合计 **+122.8**；
   **从第一个健康 mark 就武装，合计 +114~+120——两者几乎相同。**
   **∴ 真正的杠杆是激活线本身，而第 77 轮已经测出 78% 的仓位从未触及它。**

## 1. 更正我自己在本轮写下的一句错话（保留可见）

我在 `r81b` 的初稿里写过"**池子健康的中位时长是十秒量级**"。
**那是错的**，来源是我把第 81 轮另一个量——"**最后一个健康 mark 到核销的间隔 = 7 秒**"——
当成了窗口长度。**7 秒是最后那一道缝，不是窗口。**

**窗口本身：中位 493 秒、45 个已知流动性 mark、99.3% 的仓位至少有 5 个。**
这个更正很重要，因为它把结论从"来不及反应"翻成了"有充足时间却没动作"。
**我把这句错话和更正都留在脚本输出里**，因为它正是本项目的典型失败模式。

## 2. 机制链（本轮闭合到可设计的一层）

```
1,150 个仓位以粉尘核销告终（机制正确，第 80 轮）
  ↑  但池子在核销前中位健康 493 秒，期间有 45 个已知流动性 mark
  ↑  且"健康期间峰值" == "全生期峰值"（p50 都是 +0.1647）
  ↑  ∴ 每一分浮盈都在池子可交易时被观测到了
  ↑  而各臂的追踪退出要求先涨到 0.20–0.60 才武装
  ↑  78% 的仓位从未触及激活线 → 追踪退出构造上不可能触发（第 77 轮）
  ↑  因果检验：从第一个健康 mark 就武装，把这些仓位从 −944U 变成 +115U 上下
  ↑  且回撤参数 10%→50% 结果几乎不变 → 杠杆在"武装与否"，不在回撤深度
```

## 3. 这一轮**不能**得出的结论（必须一起读，且有一条是实质性的）

**它是上界，而且是刻意偏乐观的上界：**
- 池子在规则触发前死亡的仓位，**被记成在最后一个健康 mark 卖出**——即被赋予了记录所能提供的
  最有利的出价。真实成交只会更差。
- **4% 不利滑点未建模。**
- 单 epoch 样本内；虽然回撤参数不敏感这一点**削弱**（但不消除）了第 26 轮的择优陷阱。

**最重要的一条：本检验只看了"最终核销的仓位"。**
一个更激进退出的规则**同时也会作用在那些最终回本、甚至跑成大金狗的仓位上**——
**而那部分代价本轮完全没有测量。**
**∴ 本轮的 +115U 是"在这批注定死亡的仓位上"的效果，
不是"对整个账本"的效果。** 对整体是否有利，取决于它牺牲掉多少最终上涨的仓位，
**而这是未知的、且很可能决定结论的正负。**

**因此：本轮不支持任何参数改动，也不新建模块。**
用户 mandate 允许的落地形式仍是**额外策略模块 + 自己的前向证据**——
而本轮的贡献是把这个模块**应该测什么**说清楚了：
**"更早武装的追踪退出"**，而不是"更深的回撤"。

## 4. 对用户退出机制专项优化的直接输入

用户要求设计"波动率自适应止损、分批止盈、信号衰减退出、时间止损、结构确认退出等多维度组合"。
**本轮的实测把设计空间收窄到了一个维度：**

| 用户列举的维度 | 本轮实测的结论 |
|---|---|
| **武装阈值（激活线）** | **是唯一的杠杆**：0.20–0.60 的激活要求让 78% 的仓位永远不武装；去掉它，同一批仓位由 −944U 变 +115U |
| 回撤深度 | **不敏感**：10%–50% 结果几乎相同 → 不需要调它，也就不必承担调它的择优风险 |
| 时间止损 | 池子中位健康 493 秒，**时间止损按设计不会在这批仓位上触发** |
| 分批止盈 | 止盈档只在 90/1,150 个仓位所在臂上存在（第 77 轮）→ 覆盖面不足 |
| 结构确认退出 | 池子流动性就是结构指标，且它在健康期间**一直是好的**——所以"等结构确认"到的是死亡 |
| 信号衰减退出 | **未被测量**。健康期间 45 个 mark 提供了足够素材，但衰减特征本轮未构造 |

**最可验证的下一步（供用户决定）**：一个**额外策略模块**，其载体臂把追踪退出
**从入场就武装**（而不是要求先达 0.20–0.60），
并以**前向证据**回答第 3 节那个未测的问题：它牺牲了多少最终上涨的仓位。

| 脚本 | 作用 |
|---|---|

| `r81c_causal.py` | **健康区间内的因果追踪退出检验（含逐臂合约对照）** |

**新增常设规则 34**（接 §10.6）：

34. **一个"最后一个 X"的测量不是 X 的窗口长度。**
    我测得"最后一个健康 mark 距核销 7 秒"，就写下"池子健康的中位时长是十秒量级"——
    而真正的窗口是 **493 秒**。**"最后一刻"与"持续期"是两个不同的量**，
    前者描述收尾的快慢，后者描述可反应的时间。**把前者当后者，会把"时间充裕却没动作"
    误读成"根本来不及"。**
