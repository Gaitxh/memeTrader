# 后台候选行情并发提速

用户本轮要求优化后台速度和性能。改动仅涉及候选观察器的多链调度，保留既有策略、因果时间校验、账户和执行合同。

## 已确认瓶颈与改动

15:04运行快照：候选观察轮次耗时p50 7.681秒、P95 10.320秒；单币策略计算p50 56.01毫秒；持仓请求p50 1.483秒。轮次耗时包含网络、优先级等待及计算，不能全部归因于CPU。

`chain_meme_pattern_observer_once`原先逐链等待DEX行情。现改为并发获取各链的原有批次，哪个批次先完成就处理哪个。继续使用共享低优先请求槽位、持仓预留槽位、退避和每批3秒超时；请求数量、地址组成、15秒调度周期没有因本次改动增加。持仓报价仍复用原通道，失败链不消除其他链的有效观察。TaskGroup负责取消/收拢未完成任务。

本地策略计算由同一个消费协程逐币执行，每币后让出事件循环。初版让各链各自计算，测试证明另一链可能在已就绪的持仓回调之前继续计算；最终版只并发取数，保留单一消费过程。中间版本15:11:59加载，最终版本15:16:37加载，均只重启确认的Paper进程树，未重置账户。

只读剖析另发现有效策略定义重建平均约10.4毫秒，其中JSON解析约6.8毫秒；直接deepcopy约15.7毫秒，比重新JSON解析还慢。本轮没有加入无法证明失效正确性的配置缓存或额外依赖。
