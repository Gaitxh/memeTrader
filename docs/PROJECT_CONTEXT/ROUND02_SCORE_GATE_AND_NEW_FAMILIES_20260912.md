## 1. 数据/特征层实测：请求清单里哪些真的有数据

|---|---|---|
| `buys_5m` / `sells_5m` | 20,000 / 20,000 | 可用（买卖**笔数**） |
| `market_cap_usd` | 13,408 | 可用（部分） |
| `holders` | **0** | 无持有人数 |
| `buyers_5m` | **0** | 无买家人数 |
| `honeypot` / `sellable` / `buy_tax_pct` / `sell_tax_pct` | **0** | 合约权限列未落库（GoPlus 门在内存中实时判定） |
| `raw_json` | 20,000 | 原始负载仍在 |

关键发现：**`raw_json` 里其实带着 `buyers` / `sellers`（864 次出现）与 `txns`（451 次）**——
即 dexscreener/geckoterminal 的 `m5.buyers/sellers` 已经被抓取并落盘，只是**没有被解析进列**。
另无任何钱包簇 / 捆绑 / 创作者-Rug 关联表存在（相关表名检索为空）。

因此用户请求的维度分三类：

| 请求维度 | 状态 | 实现方式 |
|---|---|---|
| 买卖笔占比 | ✅ 有 | `buy_count_share`（引擎已推导） |
| LP/深度变化 | ✅ 有 | `liquidity_change_fraction` / `liquidity_retention` |
| 大单方向 | ⚠️ 代理 | 成交额增速 ÷ 笔数增速（平均单笔变大，无签名成交流） |
| 新持有人增长 | ⚠️ 代理 | 买盘占比 + 活动加速（`buyers` 列未落库，见下） |
| 前十大持有人变化 | ❌ 缺口 | 无数据源；模块内显式列入 `UNAVAILABLE` |
| 持有人集中度 | ❌ 缺口 | 只作为事实计算、从不作为硬门 |
| 捆绑（bundling） | ❌ 缺口 | 恒为 `unknown` |
| 合约权限 | ✅ 有（独立门） | `preentry_safety`（GoPlus）实时判定，非本模块 |
| 历史 Rug 关联 | ❌ 缺口 | 无创作者/Rug 关联表 |
| 社交提及速度/加速度、KOL、情绪 | ❌ 缺口（用户决定不恢复采集） | 用链上轮换代理替代，报告显式标注 |

> 诚实标注：`score149` 的 6 个维度**全部**来自已观测的链上特征；
> 9 个无源维度被写进 `score149.UNAVAILABLE`，既不参与打分也不被当作"中性/安全"。

## 2. 多维实时评分 `score149`（新增模块，纯函数、as-of、无交易权限）

`src/memetrader/score149.py`，权重：

| 维度 | 权重 | 组成（全部为已观测特征） |
|---|---|---|
| flow 买盘结构 | 0.20 | 买笔占比、成交额/笔数按龄归一的加速 |
| depth 深度 | 0.18 | 深度对数刻度、深度保留率 |
| structure 写销结构带 | 0.16 | FDV/深度（实测安全带 1–20，两侧都扣分）、池龄（<30 分钟与 >6 小时都扣分） |
| momentum 动量 | 0.16 | 30 秒对数速度、30 秒 vs 60 秒速度差（多尺度确认） |
| participation 参与度 | 0.15 | 成交额增速÷笔数增速（平均单笔变大）+ 买盘占比（**新参与者增长的链上代理**） |
| risk 风险 | 0.15 | 回撤浅度、趋势拟合 R²、**深度撤离一票否决** |

三条设计规则（都写进了测试）：

1. **缺失不等于好**：维度缺失时既不计入分子也不计入分母，覆盖率单独报告；
   门要求"分数 ≥55 **且** 覆盖率 ≥0.60 **且** 必需维度齐全"。
2. **必需维度只含 30 秒窗口无关的四项**（flow/depth/structure/risk）。
   实测 p50 每池仅 1 帧，若强制要求窗口维度，就会重演第 1 轮已修复的"严格上涨饥饿"缺陷。
3. **分数只作观察**：`snapshot()['affects'] == 'observation_only'`；它不能开仓、不能定仓、不能平仓。

### 实测分布（重载后 338 帧，来自实时遥测）

| 指标 | 值 | 含义 |
|---|---|---|
| `score_step:evaluated` | 338 | 每一帧候选都被评分（不只被臂命中的） |
| `bucket_80` / `bucket_60` / `bucket_40` / `bucket_20` | 12 / 75 / 250 / 1 | 分数集中在 40–60 档 |
| `ge_min`（≥55） | 169（**50.0%**） | 阈值把候选大致对半分开（门臂与对照臂的样本量因此可比） |
| `coverage_ok`（≥0.60） | 333（**98.5%**） | 覆盖率约束没有造成饥饿 |
| `missing:momentum` | 67（19.8%） | 单帧池没有 30 秒窗口——正是"不强制窗口维度"的原因 |
| `missing:participation` | 46（13.6%） | 同上 |
| `missing:flow` | 5（1.5%） | 极少 |

这些计数会持续累积，用来在**有前向结果之后**校准阈值（当前 55 分是按分布中位附近选的，不是拟合出来的）。

## 3. 评分门：一对额外臂（不是全局硬门）

| arm_id | 入场 | U | 持有 | 退出 |
|---|---|---|---|---|
| `alpha149_score_gate_band_v1` | `score_gate_band`（安全带 **且** 评分过门） | 1 | 30 | -20% / 追踪 +30%→15% |
| `alpha149_score_low_band_v1` | `score_low_band`（安全带 **且** 评分不过门） | 1 | 30 | 同上（逐字相同） |

同一批池子条件、同一退出合同，唯一变量是"评分在阈值的哪一侧"——
因此"评分是否真的区分结果"变成**可测量**的 A/B，而不是假设。
若两臂在 ≥20 笔自然样本后无差异，评分就**不应**升级为全局门（该结论已写进测试与规则文本）。

为什么不直接做成全局门：全局门会改变 100+ 条现有臂的入场行为，违反"不得修改任何现有策略"的约束。

## 4. 四个新策略模块（各为独立额外臂）

| arm_id | 机制 | 关键条件 | U / 持有 | 设计依据与风险定价 |
|---|---|---|---|---|
| `alpha149_momentum_persistence_v1` | `mom_persistence`（动量跟随） | 15/30/60 秒三窗口同向为正、短周期速度 ≥ 长周期且 >0、回撤 >-4%、深度 ≥3000U 且不流失；**不限定池龄** | 2 / 60 | 与"金狗/极早池"族互补：只要跨尺度持续动量 |
| `alpha149_size_informed_flow_v1` | `size_informed_flow`（聪明钱**代理**） | 成交额增速÷笔数增速 ≥1.3、买笔占比 ≥60%、深度 ≥3000U 且不流失 | 2 / 30 | 系统无钱包簇数据；命名与描述都写明"代理、非钱包证据" |
| `alpha149_early_pool_snipe_v1` | `early_pool_snipe`（新池狙击） | 池龄 ≤10 分钟、深度 ≥2000U、按龄归一加速均 >1、买盘 ≥55%、回撤浅 | **1 / 5** | 实测池龄<30 分钟写销率 22–23%（30–180 分钟仅 1.5%），故用 1U + 5 分钟上限 + -15% 止损把风险定价进去 |

四条臂都在 `RULES` 里有中文规则文本，且每臂声明 `excess_return_vs_arm`（必须超越的既有对照臂）。

## 6. 监控与迭代（本轮新增部分）

| 观察项 | 指标 | 判定规则 |
|---|---|---|
| 评分阈值是否合适 | `score_step:bucket_*` 分布 + `ge_min` 比例 | 若 `bucket_80` 长期 <5% 且门臂样本长期 <20，则阈值偏高，按分布分位（而非拟合结果）重设 |
| 评分是否有效 | `score_gate_band` vs `score_low_band` 的前向均值差 | 各 ≥20 笔后比较；无差异则评分不升级为全局门 |
| 覆盖率约束 | `coverage_ok / evaluated` | <80% 说明要求过严（当前 97.6%，安全） |
| 缺失维度 | `missing:momentum` / `missing:participation` 占比 | >50% 说明依赖窗口的维度实际不可得，需要改用无窗口代理 |
| 新模块可达性 | 每臂 `alpha149_ready:<kind>` 与准入数 | 30 分钟内 0 就绪 → 记录为"不可达"并单独诊断，不调阈值 |
| 早段狙击风险 | 该臂写销笔数与均值 | 写销率 >30% 即证实 22–23% 的先验，需进一步缩短时间上限或停用 |
