## P0-A：Token 可执行性证据

`token-universe-fixed-target-execution/v1` 已在 activation cohort 21987 后注册，固定 baseline→15/60/240m 目标，不使用事后峰值。r6 只读结果为 1,718 条：`unsupported_chain=1,587`、`insufficient_liquidity=66`、`baseline_missing=41`、`safety_unknown=20`、`modeled_executable=4`。4 条模型可执行均为 BSC 15m；这是冻结 `$35`、双边 4% 不利滑点和配置费率后的 Paper 模型，不是成交、收益或 router quote。链费、priority fee、MEV 和部分成交仍未建模；Solana 在此层仍是 unsupported。

`token-universe-jupiter-quote/v1` 是独立的 Solana 原始只读 route 账本。它只请求 Jupiter V2 `/order` 的 mint/amount/slippage 字段，不发送 taker/payer/receiver，拒绝非空 transaction，永不签名、广播或调用 execute/build/submit。只读审计在固定边界 `result.id<=239` 证明历史延迟主要来自本机队列而不是 Jupiter 响应：baseline queue p50≈1,399 秒，15m target p50≈624 秒，60m target p50≈156 秒；baseline/15m 的 total delay 绝大多数超过 60 秒。因此旧 v1 的 `round_trip_min_return` 只能作为 raw diagnostic，不能继续解释为同一固定时点的可执行证据。

本轮新增 `token-universe-jupiter-quote-validity/v1`，于 `2026-09-01T03:54:51Z` 冻结 activation cohort/raw quote result=`25941/374`。旧 v1 表与结果不修改、不删除、不回填。新层的 baseline anchor 是 baseline 快照 `source_recorded_at`，target anchor 是预先冻结的 outcome `target_at`；请求 queue 上限 30 秒、anchor→completed 上限 45 秒。请求前过期不会访问 Jupiter；响应后才过期仍保留白名单 raw quote，但不会生成往返回报。只有 baseline 与 target 均 time-valid 且 quoted，才计算覆盖层 `round_trip_min_return`。首个自然截面有 101 个 validity 终态：valid quoted 9、queue expired 36、source missing 56、valid round-trip 0。

随后定位到一个真实调度饥饿点：每个 tick 的 `limit=3` 同时限制了陈旧缺口结算和真实 provider 请求，三个已经过期且不会访问 Jupiter 的任务仍会占满本轮槽位。Runtime 现会在最多 10,000 个到期项中寻找新鲜任务，但每 tick 最多只同步终结 12 个陈旧缺口；真实 Jupiter 请求仍严格不超过 3 个、单主机间隔仍至少 2.1 秒。这个分离既避免 provider 饥饿，也避免一次写入大量缺口长期阻塞单进程。受控重启后的自然 valid quoted 已从 9 增至 18；12:45 截面共有 1,911 个 validity 终态：baseline queue expired 992、source missing 98、valid quoted 18，target baseline-not-valid 794、queue expired 9、valid round-trip 0。这个结果证明新鲜 provider 采样恢复，不证明往返回报或交易机会。它不写 Decision、Position、Trade，固定 `decision_eligible=0 / affects=none`。

质量覆盖层仍把 `same_route_return`、估算成本和“确认可执行”分开：57,291 条质量结果中 `net_executable_return_after_costs` 非空为 0。未知安全字段不会按零处理。P0-A 的工程链路已覆盖，P0-A 的自然可执行性结论尚未成熟。
