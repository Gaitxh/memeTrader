- `token_context_assessments` 追加记录高动量 Token 的项目社交声明、社区扩散、公众人物关联候选、独立报道和链上触发快照，以及模型/推理强度/token 用量。公众人物候选永不自动成为背书；除通过旧有两独立域名核验后形成的 confirmation Observation 外，评估全部仅作语境，不进入交易策略。
- 来源学习账本只在 Paper 仓位完全平仓时追加结果；当前活动 r6 没有可用于激活轮换的已平仓 Paper 样本，因此 Web 必须显示“收集样本”，不能声称已学习出优胜平台或人物。普通来源至少 20 个结果/10 天/5 个亏损，人物至少 30 个/15 天/两个平台；12 个候选观察槽位至少 5 个保留探索，critical 最多 4 个。新事件的热点 topic 只在首次接受时冻结并作描述，旧事件保持 `unknown`。
- Trend Scout 使用 `trend-lanes/v1` 五个稳定通道。每次调用会持久化选中通道、完成/失败、空结果、事件和 Observation 产出；Agent 事件必须引用本轮有效 `lane_id`。`trend-attention/v1` 只有在全局至少 20 个已接受事件，且至少两个可比较通道各自已有 20 次完成暴露、10 个运行日、5 次零产出和成熟的 60 分钟 WAIT/CANDIDATE 市场随访后，才可在 `0.80×–1.20×` 内调整 Trend Scout 通道分配；普通运行至少保留一个 round-robin 探索通道，surge 全覆盖。Paper 只作可选次级验证。当前 r6 预计仍在收集样本，尚未启用选择性分配；其永远不影响证据、决策、风险、仓位、退出或 Live。
- 首次具备有效 Token 和价格的 WAIT/CANDIDATE 现在进入 `shadow-event-followup/v1` 追加式 cohort；冻结当时最早合格来源，并以本机后来观察到的 15/60/240 分钟快照记录原始延续和区间高低点。超时缺失不回填；只有成熟的 60 分钟人物/平台结果可进入账号联合观察策略，其他维度与全部交易链路保持隔离。
- 每轮 Trend Scout 现在还会把实际选中的公开账号写入 `trend_watch_account_exposures`；完成、失败、零产出、精确原帖命中和当时的 critical/策展/学习/探索角色都保留。旧轮次不回填，新闻转述和同名人物不归因；成熟后只显示影子发现效率建议。
- `watch-attention/v1` 已取代“仅凭已平仓 Paper 调账号轮换”的偏差路径：账号发现效率和 60 分钟 WAIT/CANDIDATE 人物/平台随访必须同时成熟，Paper 只作次级验证；普通账号倍率限制为 `0.80×–1.20×`，critical 和至少 40% 探索槽位不受影响，交易链路完全隔离。
- 人物跨平台市场随访按显式 `entity_id` 复用，无映射才回退到平台；具体平台 + handle 的发现暴露不合并，未测试账号不继承其他账号的倍率。策略“具备资格”与“上轮实际选择改变”分开持久化和展示。
- RSS 使用公开 DNS/IP 校验、IP 固定、Host/SNI 保留、压缩/大小/格式门和每跳重定向检查；本机可选严格 loopback SOCKS5 代理已实测成功。
- 事件列表不返回正文，详情摘要限制 600 字；详情请求用 generation 与取消控制避免旧响应覆盖新详情。
- 访问令牌 Web 服务的钱包权限由服务启动参数固定，不能靠伪造 `Host` 解锁。
