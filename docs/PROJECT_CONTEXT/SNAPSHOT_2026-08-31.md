## 4. 本轮已证实并修复的学习语义

审计确认旧闭仓归因会在平仓时按 `event_id` 重新扫描开仓前来源。它虽然有三时间戳门，但交易记录没有 `decision_id/cohort_id`，同一事件出现多个 Token 或多轮决策时无法证明某个来源确实属于该笔成交；卖出税也没有从来源学习的净回报中扣除。

从 `paper-source-attribution/v2-decision-cohort` 起：

- 最终 CANDIDATE 的 `decision_id` 与 `create_shadow_event_cohort()` 返回的 admitted `cohort_id` 会同时写入 position、BUY 和每次 SELL。
- 前向 event-action cohort 现覆盖首次 WAIT、REJECT、CANDIDATE，并冻结事件/来源/人物/链上质量/拒绝原因的粗粒度研究标签；所有后续快照必须同时满足 `observed_at` 与本机 `ingested_at` 时间门。
- Paper execution attempt 已链接 `decision_id/cohort_id`，可区分成功、执行拒绝和旧版未链接尝试。
- 完全平仓只读取该 cohort 在决策时冻结的最早合格 `feature/confirmation`，并写入同一 decision/cohort 的 `source_utility_outcomes`。
- 买入成本包括 gross+fee；卖出净额包括 gross-fee-known_tax，滑点由真实模拟成交价和数量体现。
- 每个完全平仓 round 都写 `paper_source_attribution_attempts`；缺 decision/cohort、主键不匹配、无合格来源或现金流无效均明确记录 skipped 原因。
- 原来 1 个事件时间窗闭仓结果迁移后标为 `legacy-event-window/v1`，保留审计但不进入学习，不推测或回填 decision/cohort。
- Sources 诊断分别展示 feature、confirmation、identity、promotion；只有 observed/ingested/published 都不晚于事件首个最终 CANDIDATE 的 feature/confirmation 才计入决策时合格率与候选前关联。

这修复的是归因可审计性，不是因果识别。新账本只能描述“被选中、成交并平仓”的条件样本，不能声称某个来源、人物、平台或题材导致收益；也不改变证据、候选、风险、仓位、退出或 Live。
