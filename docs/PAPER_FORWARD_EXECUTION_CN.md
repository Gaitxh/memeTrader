# Paper 前向执行与未来 Live 验收边界

## 1. Paper 的用途

Paper 是常驻策略的前向执行实验，不是把历史价格代入后的回测，也不是为了让页面出现交易。零成交、零仓位和现金曲线平坦都可能是正确结果。评价目标是扣除已知成本后的样本外风险调整表现，同时观察回撤、尾部亏损、流动性、延迟、误报和漏检。

## 2. 禁止项

- 决策只能使用 `observed_at <= decision_at` 且 `ingested_at <= decision_at` 的证据。
- 禁止使用后来 ATH、最终赢家、后来上市、当前持有人数、事后聪明钱标签、未来 rug 标签或任何结果字段指导早期决策。
- 禁止用当前报价回填过去账户权益；没有当时可用报价时，历史或当前权益保持未知。
- 禁止覆盖已经写入的历史账户点。`paper_account_snapshots` 是 append-only；Web 只读取/下采样。
- 禁止把候选评估期间的旧报价当成必然成交价。CANDIDATE 进入 Paper 执行前必须重新取精确 Token 报价，并通过 Token 一致性、时间和最大报价年龄门。
- 退出条件触发后也必须重新报价；取不到报价、报价过期、Token 不一致或现金不足都只记录失败尝试，不能伪造成交。
- 禁止把固定滑点、DEX 中间价或安全报告误写成真实路由成交回执。
- 禁止为了增加交易数放宽 WAIT、canonical、安全、仓位或重入门槛。
- r5 失败审计不能并入 r6 表现统计，r6 不回填、不清空、不改写。

## 3. 当前成本语义

每笔新 Paper 成交持久化：

- 报价价、模拟执行价、报价时间、报价 provider 和执行请求时间；
- 买卖方向上的固定不利执行压力及美元成本；当前基线为每侧 4%，这是针对早期 meme 流动性的保守压力假设，不是假定每笔真实滑点必然为 4%；
- 通用场地费估计 `fee_bps` 当前为每笔 60 bps；Dex 报价明确识别为 PumpSwap 时使用 `pump_swap_fee_bps=125` 的保守上限。实际 Raydium/PumpSwap pool fee、creator fee 和路由费仍以未来可验证报价/回执为准；
- 安全/行情快照明确提供时的买入税或卖出税；未知税保持未知，不回填为已验证的 0；
- 模拟执行尝试的 `filled/rejected` 状态和原因。

当前没有可验证路由时，不声称已覆盖路由费、Solana priority fee、EVM gas、MEV、部分成交或链上失败。控制台会明确显示这项缺口；它是未来 Broker 验收项，不是隐含为 0。

这里严格区分三类成本：执行价相对报价的差额属于滑点/价格冲击；DEX/LP/creator/platform 收费属于场地费；Solana base/priority fee 属于链费。滑点已经反映在模拟执行价时不会再次从现金中重复扣除。当前保持一次入场；退出最多按四个止盈层级分批，每层比例作用于当时剩余仓位，安全恶化、流动性紧急、止损、叙事衰减、移动退出和最长持仓仍会一次性卖完。

## 4. 账户曲线

Runtime 最多每五分钟追加一次普通账户快照，并在 Paper 买卖后强制追加。每个点保存现金、已定价持仓市值、完整权益或 `null`、当日新增 exposure、开放/已定价仓位数和报价时间。开放仓位的最新报价超过 `paper.max_quote_age_seconds` 时，权益为 `null`；Web 不连接缺失区段，也不用未来价格补线。

## 5. Paper 与 Live 不能只靠私钥切换

策略判断、风险、订单意图和审计字段应尽量共用，降低未来迁移差异；但添加 Mainnet 私钥并不等于可以安全实盘。Mainnet Live 仍需单独完成并审核：

1. Broker/路由器和精确链/Token 身份；
2. 报价有效期、price impact、最小收到量和优先费/gas；
3. 交易模拟、签名、广播、确认、超时、重试和防重复；
4. 部分成交、失败成交、余额与链上回执对账；
5. 最大单笔/单日金额、允许链、允许路由和紧急停机；
6. 一次性小额资金的端到端 Mainnet 验证和独立复审。

在这些条件完成前，`mode` 只允许 `shadow/paper`，`live.enabled=false`，Web 不提供 Live 开关。私钥不得进入 Web 响应、日志、SQLite、Agent、项目上下文或 Git。
