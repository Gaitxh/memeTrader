## 一、完整理解需求，建立事实基线和逐项任务清单

先完整阅读本任务、相关历史要求、项目权威文档和已有交接记录，再核验当前实际实现。覆盖发现、采集、特征、策略、风控、订单执行、持仓退出、结果统计和展示，而不是只看最新报告、少数策略或页面概况。

把全部要求拆成可追踪的任务，记录任务编号、对应原始需求、当前状态、证据位置、实施内容、验收方法和未解决问题。合并重复表述，但不得遗漏实质要求。数据量较大时，可以结合全量统计、索引和按问题深入读取，不必把全部原始数据一次性载入；未实际阅读或核验的内容，不得声称已经完成审查。

建立修改前的运行与结果基线，明确代码和策略版本、配置、生效时间、统计窗口、数据覆盖及已知缺陷。区分“用户反馈”“历史文档记载”“当前已核验事实”和“待验证假设”，不得将旧结论直接当作当前状态。

## 二、优先查明交易减少或归零的真实原因

优先核实我反馈的“修改后没有交易或交易显著减少”现象：究竟是自然开仓确实停止、样本窗口不足、展示或统计异常，还是策略条件、数据链路、执行流程出现了问题。既不能预设一定是筛选过严，也不能在没有证据时解释为“市场没有机会”。

完整追踪：

**代币发现 → 数据获取与更新 → 特征可用 → 策略判断 → 风控与交易条件检查 → 订单提交与模拟成交 → 持仓更新 → 退出与结果入账。**

对各环节统计输入量、输出量、通过率、失败或拒绝原因、排队与处理耗时、数据新鲜度，并按相关链、数据源、策略和时间窗口拆分。明确统计单位和分母，避免把地址数、池数、判断次数、信号数、订单数和成交数混为一谈。优先复用已有记录，必要的补充观测不得显著拖慢交易链路。

重点排查数据缺失或延迟、字段解析错误、过期缓存、历史长度要求、预热条件、过严或相互冲突的阈值、重复过滤、冷却时间、关注池容量、任务调度、信号路由、策略注册、账户状态、交易状态机，以及计算、存储和并发瓶颈。

逐项区分必要的数据真实性与交易执行约束，以及尚待验证的策略筛选假设。对于重复、冗余或不必要地全局化的筛选，依据证据删除、调整，或改为特定策略的条件、评分、分层判断或等待机制；不得为所有策略叠加同一套过严条件，也不得为了恢复交易而伪造数据、绕过成交真实性检查或无依据地全面放宽规则。

## 三、完整复盘样本，解释为什么没有抓住机会

研究对象为我提供的完整代币地址清单，见附录 A。保留原始顺序和重复记录，另行建立核验、去重和数据关联后的研究索引。核实所属链、代币与交易池身份，避免错误合并或关联；不得仅凭地址形式、后缀或名称猜测其所属链、平台及交易属性。疑似缺失或格式异常的地址应单列待核验，不得擅自补齐或改写。

这些地址是我从平台热门中事后选出的上涨样本线索，不应未经核验就全部标记为成功、可交易或能够获利的“金狗”。它们用于发现能够泛化到未来新代币的规律，不是用于设置指定地址白名单、只优化这些币，或反复拟合它们的最佳买卖点。

对每个能够获得证据的样本，重建创建或相关池建立、系统首次发现、首次取得可用数据、策略首次评估、各次关键拒绝、实际买入、持仓判断和退出的时间线。分别解释：为什么没有发现或发现太晚，为什么发现后没有及时获得数据，为什么没有买入或买入太晚，以及为什么买入后过早卖出、持有过久或无法退出。

特别区分“新创建后迅速上涨”和“创建已久后重新启动”，并分析持续上涨、阶梯上涨、冲高回落、回撤后继续上涨及中等幅度短期波动等不同路径。历史走势分类可用于事后研究，但实时候选识别只能依据当时已经可得的信息。

将问题分为发现问题、数据问题、策略问题、执行问题、退出问题和系统当时确实无法识别或交易的机会。早期数据、实际可见时间或关键日志缺失时，明确证据缺口，不得利用今天补查到的信息声称系统当时已经知道。

同时建立相应时期、链和可比市场条件下的普通、失败及未上涨样本作为对照，检查相似早期信号在这些币上会造成多少误判和损失。不能只研究后来上涨的币，再推导出“早期一定存在可稳定识别的特征”。

## 四、基于实际可得数据研究派生特征与组合

先梳理系统实际拥有的字段、来源、更新时间、采样频率、缺失情况和计算成本，再提出特征方案。不得假设系统已经具备尚未接入的链上、钱包、社交或其他数据，也不要把研究目标建立在超出资源能力的数据上。

可以围绕已有且可靠的价格、成交量、交易笔数、买卖分布、流动性、代币或池龄、历史活跃度等数据，探索变化率、加速度、持续性、回撤与恢复、量价关系、活跃度突变、买卖不平衡、多时间窗口一致性，以及相对自身历史基线的异常程度。以上仅为候选方向，具体取舍取决于实际字段与数据质量，不是要求全部实现。

每个特征都要明确计算公式、所需数据、时间窗口、最小有效样本、缺失和过期处理、可用时间及计算成本。区分关键交易数据缺失与非关键研究字段缺失，不能把缺失当作零，也不能因为某个非必要字段缺失就无差别阻断全部策略。

同时检验单个特征和组合是否真正有增量价值，避免堆叠高度重复的条件。把“可能存在有效特征组合”作为需要证据支持、允许被否定的研究假设，而不是必须证明成立的结论。

若某项需求需要昂贵数据或复杂计算，优先寻找现有字段的低成本代理、增量计算或近似实现，并验证其误差及适用边界。近似不能满足要求时，应调整、暂缓或取消该策略，说明原因，而不是拖慢整个系统。

## 五、广泛设计并实现不同场景下的策略

不要局限于我提出的例子。结合样本、对照、历史策略和前向结果，探索不同生命周期、活跃度和市场环境下的入场、持仓与退出方法。结合必要的公开资料和开源实现开展调研，记录来源及适用条件；外部结论只能作为候选依据，必须核验与本系统数据、成本和资源条件的兼容性，不能照搬或当作本项目已经验证的事实。

研究范围至少同时覆盖两类目标：一类是尽可能早地发现和识别新币启动或老币重新启动，在可交易条件成立时入场，并在趋势仍有证据支持时避免过早离场；另一类是针对涨幅不一定很大、但存在短期可执行价差的机会，研究果断退出、严格计入成本的短持交易。

可进一步探索持续趋势与回撤承接、阶梯或快速上涨后的衰减识别、二次启动、动态止盈与利润保护，以及依据当时可观察环境选择或组合策略等方向。不要求逐一照搬这些方向，也不限制提出其他符合现有能力的方案。

“早买并卖在最高点”应转化为可检验的目标：减少可避免的发现和入场延迟，提高有效上涨阶段的收益捕获，减少不必要的过早退出和利润回吐。不得以事后最高点制定实时卖出规则，也不能把每次未卖在最高点都判定为策略错误。

“多交易就能多赚钱”必须以扣除成本和损失后存在正向净期望为前提。“我们的获利或投入小于对方撤池成本，所以能够安全获利”只能作为待检验假设，不能成为安全保证、放松执行真实性要求或忽略尾部损失的依据。允许在隔离的模拟策略中研究高风险短持机会，但必须真实计入撤池、无法退出、滑点恶化、连续亏损及可能的全部本金损失。

每项候选策略都应给出可执行定义：适用场景与机制假设、数据依赖、入场条件、仓位或模拟交易规模、持仓管理、退出规则、缺失数据处理、失败情形、成本假设、资源开销和验证方法。具备合理机制且通过必要工程检查的方案，应进入可区分、可追踪的模拟前向试验，而不是停留在概念说明或等到“确定盈利”才实现。

## 六、全面整理、修订和整合现有及退役策略

覆盖截至当前所有能够找到的策略与版本，包括正在运行、暂停、退役、历史实验和参数变体，不得只审查当前页面展示的策略。

按实际会改变买入、持有和卖出行为的规则整理策略，识别真正不同的机制、完全重复的行为及相似策略族。允许有明确假设的参数变体，但不能用大量无实质差异的复制策略代替研究成果，或将重复运行的结果当作额外独立证据。

分别判断收益或亏损更可能来自策略机制、市场环境、数据与工程缺陷、交易成本、样本选择还是统计口径。对退役策略说明退役原因；因工程问题失效的策略，在缺陷修复后可以重新评估，但不得把修复前后的结果混合后声称策略改善。

可以直接优化现有策略，也可以新增独立策略，或将不同策略在不同场景下的有效规则整合为新策略。整合要说明场景识别、规则选择、冲突处理和资源影响，不是简单把所有筛选条件取交集，或把所有买入信号无条件叠加。

修改必须保留旧版本、原参数、历史记录、生效时间和可复现证据。已有持仓的退出规则及迁移方式需要明确，不能因更新造成隐性重置。新策略必须实际接入判断、模拟成交、持仓退出和统计流程，而不是只完成注册或展示。不要为添加策略清空历史数据、重置所有账户或抹去原有结果。

## 七、优化发现和采集的覆盖、频率与资源调度

在现有资源和接口约束内，尽可能扩大有效发现覆盖、缩短新标的数据等待时间，并提高重点标的数据的新鲜度。当前数据链路已经稳定且能够满足需求时，不要仅为了增加功能而引入新接口、付费依赖或复杂基础设施。确有现有能力无法解决的关键缺口时，先说明证据、收益、成本和替代方案，再按实际权限处理。

核实已有接口的真实限速、批量能力、错误类型及有效吞吐。目标是减少重复和无效请求、提高单位配额产生的有效数据量，而不是机械地持续打满限额。合理利用批量查询、共享缓存、去重、并发控制、退避和任务合并，避免限流重试挤占正常请求。

重点设计随代币数量增长仍可运行的分层调度：已持仓、待退出及处于关键执行阶段的标的需要优先获得必要更新；策略重点关注和接近触发的标的需要更及时的数据；新发现标的需要保有初始评估机会；低活跃和冷却标的可以降低频率，但老币仍应保留重新活跃的检测机会。

优先级不能演变成其他标的长期得不到服务。应设置有依据的预算、容量、轮转和降级机制，兼顾新币覆盖、老币重新启动与持仓安全，避免关注名单无限扩张、队列持续积压，或新增发现挤占退出数据。

持续观察发现速率、有效采集量、配额利用、限流与错误率、各层覆盖和数据新鲜度、排队耗时及重点标的更新延迟。采集频率应服务于策略真正需要的时间尺度，避免重复读取未变化的数据，也避免用过期数据做快速买卖判断。

## 八、优化计算、存储、策略判断和整体稳定性

先测量性能瓶颈，再选择有针对性的改进。可以调整参数、模块边界或必要的架构，但应以解决已证实的问题为目的，并保留回退路径。重点检查重复计算、全量扫描、逐策略重复请求、同步阻塞、数据库锁竞争、过量写入、无界队列，以及历史研究或报表计算对实时链路的影响。

在必要且适用时采用共享特征、增量计算、有界缓存、合理索引、批量读写、冷热分层和任务隔离。以实际瓶颈决定实现，不要求为了优化而新增一整套复杂架构。

确保策略使用的数据时间口径一致、版本可辨认、计算可复现。优化不能通过丢失关键记录、隐藏错误、误用缓存、错配代币或池、降低数据真实性来换取表面速度。研究和审计所需的重任务应避免阻塞实时路径。

每项重要改动都要比较修改前后的延迟、吞吐、资源使用、数据质量和交易链路表现。若新增策略或功能造成明显退化，应优化实现、降低开销、更换近似方法、隔离或回退该项改动，不得要求全系统为单个策略承担不合理成本。

## 九、严格禁止未来数据，以自然模拟前向结果验证

每次策略判断只能使用当时系统已经实际获得且可用的信息。明确区分事件发生时间、数据采集或接收时间、特征可用时间和决策时间；不得因为某条信息描述的是较早事件，就认定系统在该事件发生时已经知道它。

禁止用事后热门排名、最终涨幅、后续成交、峰值、未来最高最低价、后补数据或后来才能计算的完整统计量参与历史入场和退出判断。事后标签可以用于评估，不能反向进入当时的决策。无法恢复当时可见性的信息，应说明边界，不得伪造严格历史重放。

区分历史探索、离线验证与策略生效后的自然前向结果。避免把用于发现规律的同一批样本反复用于证明有效；在可行范围内采用时间隔离、代币隔离和不同环境验证，识别热门样本选择、幸存者偏差及重复样本等影响。

模拟成交必须与系统当时可观测、可验证的执行条件一致，明确模型假设与未知项。按适用情形计入手续费、滑点、执行延迟、价格变化及买卖失败影响，避免重复扣费或漏计成本。不能默认行情价必然成交、流动性足够、退出必定成功，或将失去报价和无法退出的仓位继续按旧价格表现为已实现盈利。

结果至少覆盖净收益及其分布、交易数量、胜率与盈亏比、持仓时间、回撤与尾部损失、买卖成功情况、未实现与已实现收益、样本覆盖，以及新增机制相对基线的变化。分别说明独立代币、交易和策略账户的样本数量，不能混称。

证据不足时明确标记“样本不足”“仅通过工程验证”“尚无自然成交”或“尚未证明盈利”。代码实现、测试通过、策略运行、自然成交和盈利有效性是不同状态，不得混为完成。不能用人工制造的信号、回填订单或选择性展示替代自然前向结果。

## 十、小步落地，合理使用多 agent，避免只分析不实施

按“建立基线与定位问题 → 修复关键阻塞 → 实现可运行的策略或改进 → 工程测试与集成 → 自然前向观察 → 根据结果复核修订”推进。各阶段可以合理并行，不必等一份庞大报告全部完成才开始必要修复，也不能长期只做基础设施而没有策略成果。

对于已有权限内、可回退、不增加外部费用且不涉及实盘的常规改动，直接推进，不要反复请求确认。涉及超出权限、新增支出、不可逆删除或实盘操作时，不得擅自执行；记录阻碍并继续处理其他可完成任务。

环境允许时，可以使用实际可调用的高能力模型和较高推理配置，通过多个 agent 分工开展样本复盘、特征研究、策略设计、性能诊断、代码实现与独立审查。记录实际使用的能力和产出，不得虚构模型身份、推理等级、子 agent 数量或协作结果。

任务分工应具体，包含输入、目标、约束和验收证据，避免多个 agent 重复研究或冲突修改运行代码。遇到长期卡住的问题，可以寻求独立分析或改变方法，但不能无限重试、反复重写计划，或拖住其他可独立推进的工作。

## 十一、持久化项目记忆，并更新系统“更新历史”
