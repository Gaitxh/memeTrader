# Public Feed Bridge

Chrome/Edge Manifest V3 extension for forwarding newly rendered **public** feed items from already-open pages to `http://127.0.0.1:8765`.

It does not read cookies, credentials, DMs or browser history; it does not auto-scroll or perform social actions. Items require a parseable recent `<time datetime>` so an old page loaded today is not silently treated as a live historical observation. The outbound queue is persisted in `chrome.storage.local` and retried after browser-worker or robot interruptions.

When enabled in the options page, two inactive tabs rotate through the local public-account watchlist: one critical account and one normal account per minute. This only navigates public profile URLs so the existing content script can capture recent rendered posts. It does not scroll, follow, like, reply, repost, or read credentials. Keep the browser signed in where a platform requires login to render public posts.

The local Web watchlist may include an optional stable `entity_id`. The extension forwards it only when the rendered author exactly matches the configured platform and handle. The Runtime independently checks the same local watchlist before persisting that ID, so arbitrary page content cannot choose a cross-platform deduplication identity. Display names and follower counts are never used to infer ownership.

For an exact X status URL that represents a configured account's repost, the rendered article belongs to the original author while the page URL belongs to the reposting account. Version 0.6.7 preserves both facts instead of mislabeling either one: `source/author/source_entity_id` identify the configured repost actor, `source_action=repost` records the action, and `content_author/content_url` retain the original post lineage. Freshness uses the repost status Snowflake time, not the older original post time. A repost remains an observed attention action, not proof of endorsement, independent confirmation, Token identity, safety, or trade eligibility. To reduce browser memory, critical and normal account rotation now share one page while exact priority-post follow-up keeps a second page; critical accounts are still revisited about once per minute.
